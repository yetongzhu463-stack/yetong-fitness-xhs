# YETONG 技能组：本地封装说明

本文件记录本地预览 ZIP 的封装边界；GitHub 远端和手机云端 Agent 的安装状态必须分别实测。先前七技能版曾在临时隔离项目中完成离线复制、资源哈希和档案门槛校验；短名重构后的实际通过范围以重新运行的验证记录为准，不能沿用旧结果直接宣称新包已安装。封面模块的合成素材行为测试记录仅保留在维护者本地，不进入运行包或公开仓库。本组当前服务本地线下健身教练的小红书内容创作，不用于全国线上招生或教同行获客。

## 三条服务线与首次展示

**小红书内容创作已可用；朋友圈营销和业绩管理是规划方向，目前没有对应的专项 Skill。** `yetong` 主入口和 `yetong-dna` 人物档案是共同基础，不另算第四类。叶童提供的“约五年实践、近 2,000 篇内容创作与复盘”是经验来源口径；公开包仅含提炼后的方法和结构，不含近 2,000 篇案例全文，也不保证流量、成交或业绩增长。面向用户的说明见 `docs/START_HERE.md` 与 `docs/SKILL_CATALOG.md`。

安装结束不会跨 Agent 自动弹出欢迎目录。首次对话可让用户说：“使用 `yetong`，展示当前实际已安装的技能及三大类；缺失的标未安装，尚未开发的标规划中。”主入口应先核验能力登记表和可读取目录，再介绍已可用项；不能只因为目录文案存在就宣称专项 Skill 可运行。

## 当前八个 Skill 的关系

```text
yetong                 主入口：判断先访谈、出题、写稿、拟标题、体检还是做封面
├── yetong-dna          本人建档：六组一次展示，支持一段语音回答
├── yetong-topic        本地选题：客群问题 × 真实素材
├── yetong-copy         单篇文案：已选题 × 本人表达
├── yetong-review       五关体检：已有选题／草稿 × 本地会员 × 本人证据
├── yetong-title        标题定稿：具体问题／正文 × 本地顾虑 × 可公开证据
├── yetong-cover        封面与成图接力：具体选题／草稿 × 本人素材与授权 × 本地场景
└── yetong-update       本包版本检查／更新：官方清单 × 当前安装 × 保留人物档案
```

当前八个目录应作为同一套能力一起保留。主入口读取 `yetong/references/capability-registry.json`，核验目标 Skill 是否可用；缺少依赖时应停止该阶段。更新能力可修复缺失文件，无需人物档案，不先以完整登记校验阻断更新。每位教练的人物档案须由本人访谈、确认，保存在包外的独立私人位置。`active` 只表示档案中已记录的事实得到确认，不表示缺失的故事、文风或肖像可以补造。

## 后续增加模块

可以在维护者自己的环境使用 DBS Skill Maker 制作一个新 Skill，但制作工具不是本包的运行依赖，不随包分发。新模块完成后，在主入口登记表写明用途、适用与排除情境、档案和输入门槛、产品适配、所需文件，再运行 `python3 yetong/scripts/validate_registry.py` 校验。`packaging/build_bundle.py` 只收录登记表中启用且逐项列明的 `package_files`；多放一个目录不会自动进入包或参与路由。登记、静态校验和打包通过后，仍须做新模块与旧模块之间的行为回归。

发布前运行 `python3 packaging/build_release_manifest.py` 生成随主入口安装的版本、模块和资源哈希清单，再用 `--check` 核对其与源文件一致。清单不对自身做哈希，避免循环；其余运行文件均由白名单生成。运行文件和清单一起推送后，`yetong-update` 才能从固定远端提交同步新模块。学员首次获得此模块需重新安装一次；后续可直接说“更新叶童技能”。更新脚本只触碰当前安装内受管的本包文件，保留未知文件、私人档案和其他技能，并备份／回滚；平台托管技能库需要用该平台的更新入口，不能把文件改动冒充云端持久注册。

## 首次使用的实际顺序

1. 首次建档使用指定开场，一次展示六组问题，支持一段语音／文字：业务与场馆优势、到店会员与主力人群痛点、真实客户问题、本人身份与专业交付、高光经历、客户选择理由。第一组中性询问真实服务城市，再请用户补充商圈，不预设地点；已知信息直接沿用。六组就是默认建档范围，回答后集中整理，只补问关键缺口并核对公开边界，经本人确认才激活。不要求凑满三件高光、证书或案例，旧版已激活 schema 2 档案继续可用。
2. 有已激活档案但没有具体题时，主入口交给选题 Skill；它只为该教练所在地的线下会员出题，并标注人设型、营销型、利他型或流量互动型。
3. 有具体题或会员问题时，主入口交给文案 Skill。本人语言样本不足时输出待校准试稿，请教练指出不像自己的句子；不得把其他教练的经历和口吻套过来。
4. 有具体选题或草稿、只要诊断时，主入口交给体检 Skill。它不自动整篇改写，也不把内容质量诊断说成平台审核通过。
5. 有具体选题、原标题或草稿、只要标题时，主入口交给标题 Skill；没有正文则把候选标为待正文兑现。
6. 有具体且选定的本地会员选题或草稿、要封面构图／实拍计划／生图提示词时，主入口交给封面 Skill。先交接本人可用的照片、场馆或会员素材及对应授权；默认交付方案与清单。若已给完整成图指令、当前工具可用且素材授权齐备，封面 Skill 追问“直接生成／继续优化提示词”；短回复仍路由回同一封面任务。只有用户明确选择生成或原请求已明确要求成图、并再次核对条件后，才调用生图工具。

## 包内与包外

运行包应只包含主入口与登记表所列模块的 `SKILL.md`、逐项批准的必要 `agents/`、`references/`、`scripts/`，各目录的 MIT 许可证，以及面向用户的说明和校验清单。`docs/START_HERE.md`、`docs/SKILL_CATALOG.md` 应随面向用户的交付一同提供；是否进入预览 ZIP 以实际打包清单及哈希核验为准。用户已同意公开提炼后的四类内容框架地图；原课程 PDF、右侧完整例文、人物档案、会员资料、真人试稿、开发评测与工作区绝对路径都不进入运行包。原 PDF 本身不受本包 MIT 许可覆盖。

公开仓库另提供 `packaging/test_remote_install.py`，用于推送后按登记表在临时项目核对本次 Skill 集合与菜单，以及包更新脚本的文件事务测试。本地合成教练档案、行为冒烟脚本和详细验证记录不属于学员安装必需文件；未单独确认公开前留在维护者工作区，不因发布运行包而一并推送。

本包是可检查的本地文件封装，不是公开安装器。先前合成档案冒烟跑通过主入口 → 选题 → 文案、主入口 → 内容体检、主入口 → 标题、主入口 → 封面，以及未激活拦截；封面模块还测过缺本人照片、会员照片无授权、无依据效果保证和跨教练留出样本。这些旧名阶段的证据不能替代短名版的重新回归；远端 `npx` 安装也需按推送后的仓库版本另行验收。真实图片生成和手机云端 Agent 仍未验证。MIT 许可证和框架地图公开权限已由用户确认；不要把隔离测试当作跨教练真人或获客效果验证。

## 已有证据与剩余边界

- 已有叶童本人档案的真实选题、文案与语气反馈；旧版主入口用其已激活档案做过非盲行为冒烟。新增体检模块目前只用合成 active／draft 档案做过行为测试，未用叶童本人或第二位教练做真实内容体检。
- 新增标题模块不含 DBS 的标题公式库、旧例或“验证过的爆款”主张；它以本地会员问题、本人证据和正文承诺决定标题。合成档案验证结果见本地标题验证记录。
- 新增封面模块取用原个人版的抽象视觉原则，不复制个人科技领域的产品模板、案例或真人形象；其合成行为样本及限制保存在维护者本地，实际图片生成和肖像授权仍须逐次核对。
- 六组一次性访谈支持语音转录，新增资料供内容各阶段按需取用；结构检查、合成输入和旧档案兼容检查不等于真实语音识别或另一位教练的耗时验证。
- 第二位真人教练试用不是当前本地封装的验收条件；这也意味着尚不能声称跨教练个性化效果已获真人验证。
- 不把用户给出的爆款元素概率或播放量数字当作保证，不承诺会员训练结果、内容播放量或到店成交。
