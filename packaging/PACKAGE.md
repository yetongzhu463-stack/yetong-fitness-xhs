# 叶童健身教练小红书 Skill：本地封装说明

本文件记录本地预览 ZIP 的封装与测试，不声明 GitHub 远端的安装状态。四个 Skill 已在临时隔离 Codex 项目中经本地解压与复制安装测试，不代表已安装到用户的全局 Skill 目录。目标是让健身教练用自己的已确认人物档案，围绕所在地的线下潜在会员做小红书选题与文案；不用于全国线上招生或教同行获客。

## 当前四个 Skill 的关系

```text
yetong-fitness-xhs           主入口：判断先访谈、出题还是写稿
├── yetong-fitness-xhs-profile  本人建档：默认短访谈，按需深访
├── yetong-fitness-xhs-topic    本地选题：客群问题 × 真实素材
└── yetong-fitness-xhs-copy     单篇文案：已选题 × 本人表达
```

当前四个目录应作为同一套能力一起保留。主入口读取 `yetong-fitness-xhs/references/capability-registry.json`，核验目标 Skill 是否可用；缺少依赖时应停止该阶段，不临时冒充。每位教练的人物档案须由本人访谈、确认，保存在包外的独立私人位置。`active` 只表示档案中已记录的事实得到确认，不表示缺失的故事或文风可以补造。

## 后续增加模块

可以在维护者自己的环境使用 DBS Skill Maker 制作一个新 Skill，但制作工具不是本包的运行依赖，不随包分发。新模块完成后，在主入口登记表写明用途、适用与排除情境、档案和输入门槛、产品适配、所需文件，再运行 `python3 yetong-fitness-xhs/scripts/validate_registry.py` 校验。`packaging/build_bundle.py` 只收录登记表中启用且逐项列明的 `package_files`；多放一个目录不会自动进入包或参与路由。登记、静态校验和打包通过后，仍须做新模块与旧模块之间的行为回归。

## 首次使用的实际顺序

1. 教练说出自己的城市／服务区域、主要到店会员、一个真实客户问题和一个确实在做的服务动作。人物访谈整理公开边界，请本人确认后才激活基础档案；不强迫第一次讲完整人生。
2. 有已激活档案但没有具体题时，主入口交给选题 Skill；它只为该教练所在地的线下会员出题，并标注人设型、营销型、利他型或流量互动型。
3. 有具体题或会员问题时，主入口交给文案 Skill。本人语言样本不足时输出待校准试稿，请教练指出不像自己的句子；不得把其他教练的经历和口吻套过来。

## 包内与包外

运行包只包含主入口与登记表所列模块的 `SKILL.md`、逐项批准的必要 `agents/`、`references/`、`scripts/`，以及各目录的 MIT 许可证、首次使用说明、本说明和校验清单。用户已同意公开提炼后的四类内容框架地图；原课程 PDF、右侧完整例文、人物档案、会员资料、真人试稿、开发评测与工作区绝对路径都不进入运行包。原 PDF 本身不受本包 MIT 许可覆盖。

本包是可检查的本地文件封装，不是公开安装器。已用 `npx skills add` 从**解压后的本地目录**将四个 Skill 复制进临时 Codex 项目，核对文件哈希、登记表和激活／未激活档案门槛；还在临时安装环境用合成档案实际跑通主入口 → 选题 → 文案，以及未激活拦截。直接从 ZIP 路径安装、远端仓库安装和其他 Agent 的结果须分别验证。MIT 许可证和框架地图公开权限已由用户确认；不要把隔离安装当作跨教练效果验证。

## 已有证据与剩余边界

- 已有叶童本人档案的真实选题、文案与语气反馈；新版主入口用其已激活档案做过非盲行为冒烟，同时用合成未激活档案检查拦截。四个 Skill 在开发工作区分别有结构及脚本检查。
- 默认短访谈是近期改动，目前只完成合成基础档案的门槛兼容检查，尚未测得另一位教练的真实耗时。
- 第二位真人教练试用不是当前本地封装的验收条件；这也意味着尚不能声称跨教练个性化效果已获真人验证。
- 不把用户给出的爆款元素概率或播放量数字当作保证，不承诺会员训练结果、内容播放量或到店成交。
