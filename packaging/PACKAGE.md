# YETONG 技能组：本地封装说明

本文件记录本地预览 ZIP 的封装边界；GitHub 远端和手机云端 Agent 的安装状态必须分别实测。先前七技能版曾在临时隔离项目中完成离线复制、资源哈希和档案门槛校验；新增模块后的实际通过范围以重新运行的验证记录为准，不能沿用旧结果直接宣称新包已安装。合成素材行为测试记录仅保留在维护者本地，不进入运行包或公开仓库。本组当前服务本地线下健身教练的小红书内容创作与具体课程朋友圈营销，不用于全国线上招生或教同行获客。

当前封装版本为 `0.9.0`，新增 `yetong-timer` 每日热点选题，总计 10 个 Skill。发布前核对显式白名单，发布后从 GitHub 在临时隔离项目验证安装及逐文件一致性；不发布私人档案或测试输出。安装、新版本同步与实际后台任务创建是三个不同动作，Skill 交付、白名单、ZIP 或远端安装通过都不构成定时任务的到点执行验收。

## 三条服务线与首次展示

**小红书内容创作与课程产品朋友圈营销已交付；泛朋友圈人设／日常运营尚未覆盖，业绩管理仍规划中。** 每日热点选题归内容线，不另设第四类或通用任意任务服务。`yetong` 主入口和 `yetong-dna` 人物档案是共同基础。叶童提供的“约五年实践、近 2,000 篇内容创作与复盘”是经验来源口径；公开包仅含提炼后的方法和结构，不含近 2,000 篇案例全文，也不保证流量、成交或业绩增长。面向用户的说明见 `docs/START_HERE.md` 与 `docs/SKILL_CATALOG.md`。

安装结束不会跨 Agent 自动弹出欢迎目录。首次对话可让用户说：“使用 `yetong`，展示当前实际已安装的技能及三大类；缺失的标未安装，尚未开发的标规划中。”主入口应先核验能力登记表和可读取目录，再介绍已可用项；不能只因为目录文案存在就宣称专项 Skill 可运行。

## 当前 Skill 的关系

```text
yetong                 主入口：判断内容阶段、每日热点选题、课程朋友圈营销或包内更新
├── yetong-dna          本人建档：六组一次展示，支持一段语音回答
├── yetong-topic        本地选题：客群问题 × 真实素材
├── yetong-timer        每日热点选题：本人 active DNA × 热点方法 × 已核实原生调度，每次 3 题
├── yetong-copy         单篇文案：已选题 × 本人表达
├── yetong-review       五关体检：已有选题／草稿 × 本地会员 × 本人证据
├── yetong-title        标题定稿：具体问题／正文 × 本地顾虑 × 可公开证据
├── yetong-cover        叶童原版封面：单题编号问答 × 本人图1 × 3:4 真人实拍
├── yetong-promo        课程朋友圈：本人 DNA × 独立产品卡 × 每日推广与文案
└── yetong-update       本包版本检查／更新：官方清单 × 当前安装 × 保留人物档案
```

当前登记的目录应作为同一套能力一起保留，菜单数量由登记表动态读取。主入口读取 `yetong/references/capability-registry.json`，核验目标 Skill 是否可用；缺少依赖时应停止该阶段。更新能力可修复缺失文件，无需人物档案，不先以完整登记校验阻断更新。每位教练的人物档案须由本人访谈、确认，保存在包外的独立私人位置。`active` 只表示档案中已记录的事实得到确认，不表示缺失的故事、文风或肖像可以补造。

## 后续增加模块

可以在维护者自己的环境使用 DBS Skill Maker 制作一个新 Skill，但制作工具不是本包的运行依赖，不随包分发。新模块完成后，在主入口登记表写明用途、适用与排除情境、档案和输入门槛、产品适配、所需文件，再运行 `python3 yetong/scripts/validate_registry.py` 校验。`packaging/build_bundle.py` 只收录登记表中启用且逐项列明的 `package_files`；多放一个目录不会自动进入包或参与路由。登记、静态校验和打包通过后，仍须做新模块与旧模块之间的行为回归。

发布前运行 `python3 packaging/build_release_manifest.py` 生成随主入口安装的版本、模块和资源哈希清单，再用 `--check` 核对其与源文件一致。清单不对自身做哈希，避免循环；其余运行文件均由白名单生成。运行文件和清单一起推送后，`yetong-update` 才能从固定远端提交同步新模块。学员首次获得此模块需重新安装一次；后续可直接说“更新叶童技能”。更新脚本只触碰当前安装内受管的本包文件，保留未知文件、私人档案和其他技能，并备份／回滚；平台托管技能库需要用该平台的更新入口，不能把文件改动冒充云端持久注册。

## 首次使用的实际顺序

1. 首次建档使用指定开场，一次展示六组问题，支持一段语音／文字：业务与场馆优势、到店会员与主力人群痛点、真实客户问题、本人身份与专业交付、高光经历、客户选择理由。第一组中性询问真实服务城市，再请用户补充商圈，不预设地点；已知信息直接沿用。六组就是默认建档范围，回答后集中整理，只补问关键缺口并核对公开边界，经本人确认才激活。不要求凑满三件高光、证书或案例，旧版已激活 schema 2 档案继续可用。
2. 有已激活档案但没有具体题时，主入口交给选题 Skill；它只为该教练所在地的线下会员出题，并标注人设型、营销型、利他型或流量互动型。
3. 有具体题或会员问题时，主入口交给文案 Skill。本人语言样本不足时输出待校准试稿，请教练指出不像自己的句子；不得把其他教练的经历和口吻套过来。
4. 有具体选题或草稿、只要诊断时，主入口交给体检 Skill。它不自动整篇改写，也不把内容质量诊断说成平台审核通过。
5. 有具体选题、原标题或草稿、只要标题时，主入口交给标题 Skill；没有正文则把候选标为待正文兑现。
6. 有具体且选定的本地会员选题或草稿、要封面构图／生图提示词／文字排版时，主入口交给封面 Skill。薄接入层先核验本人 active 档案、本地业务和素材权限，再完整读取 `yetong-cover/original-cover-workflow.md`，执行原版单题编号流程。已有主题时跳过内容提问，从尚未确认的构图选择开始；五种构图与“根据内容推荐”、图1人物参考、产品／辅助素材、动作、背景、封面文字均按原版顺序。用户已给信息不重复问，当前阶段的编号回复不重新路由。缺图1时停在上传，不以无人物海报替代。原版参考保持 3:4 真人实拍、白色与暖橙黄 `#F5A623`、上下巨字、无漫画粗描边；给定文字原样使用，未提供封面文字时给三候选，不修改笔记发布标题。完成方案、完整提示词、排版清单与约束后询问“需要根据这份提示词完成封面吗？回复‘直接生成’或‘继续优化提示词’。”用户只要提示词则不催成图；工具／素材／授权缺失时如实说明。只有明确生成请求且条件满足时才调用生图能力。

7. 有本地课程简介、已有课程营销计划或具体课程朋友圈草稿时，进入 `yetong-promo`。它读取本人 active DNA 和独立产品资料卡，梳理人群、痛点、优势、证据及每天推广任务，匹配四类宣传逻辑与现有营销型子类推荐文案。课程可以先由用户构造为草案，草案只用于明确标记的内部提纲，不擅自写成在售；对外成稿须已确认真实可交付的课程内容，价格与权益仅在相应事实已确认时写，非必要价格缺失不阻止课程介绍。只缺课程资料不重新做人设访谈；身份、城市、业务能力或公开承诺冲突才回 DNA。接续写某天、改计划天数或改文案时保留原产品卡，不转到小红书选题／文案。反馈、对比、收款、复购和名额均须真实，素材授权分项核对；没有证据时安排收集或用真实说明替代，不伪造热销。

8. “根据我的DNA帮我进行定时任务选题”“每天定时给我3个热点选题”、一次本人热点试跑或已注册热点任务的实际运行进入 `yetong-timer`。它读取当前教练本人 active DNA 和热点方法，每次固定 3 题，受众仍是本地潜在会员；抖音等平台只作为热点来源，可通过泛曝光建立专业信任，不强卖课、不教同行获客，不擅自扩写脚本、发布标题、封面或发布。普通“出5题”仍进 `yetong-topic`；课程“朋友圈每天4条计划”仍进 `yetong-promo`，计划不自动变成调度。

每日任务创建须核实当前环境的宿主原生能力，绑定本人 DNA 和热点方法，并确认后台执行时可读取相应文件；缺时间或时区仅补问，不擅定 9 点或一律中国时区。创建前核对已有同类任务，避免重复。豆包／WorkBuddy 原生能力须在当前环境核实，不能编造创建 API 或声称手机云端已实测。只有返回可核对的任务标识、启用状态、时间及时区，才按实际结果报告创建状态；取消或其他调度管理可用宿主原生任务列表，模块不承担通用管理。

## 包内与包外

运行包应只包含主入口与登记表所列模块的 `SKILL.md`、逐项批准的必要 `agents/`、`references/`、`scripts/`、原版工作流辅助文件，各目录的 MIT 许可证，以及面向用户的说明和校验清单。`docs/START_HERE.md`、`docs/SKILL_CATALOG.md` 应随面向用户的交付一同提供；是否进入预览 ZIP 以实际打包清单及哈希核验为准。用户已同意公开提炼后的四类内容框架地图；本轮又明确授权纳入其个人 `yetong-xhs-cover` 的逐字原版工作流及 `visual-language.md`、`layout-templates.md` 两份参考。原版辅助文件名为 `original-cover-workflow.md` 而非第二个 `SKILL.md`，避免安装器发现额外模块；原文中的相对链接仍指向同目录下 `references/`。旧 `cover-method.md`、`layout-patterns.md` 已移到 `packaging/history/cover-v0.6.0/` 保留历史源码，不留在可安装 Skill 目录，避免安装器把旧规则也复制进去；不在运行白名单，也不作为执行方法。个人照片、原课程 PDF、右侧完整例文、人物档案、会员资料、真人试稿、开发评测与工作区绝对路径都不进入运行包。原 PDF 本身不受本包 MIT 许可覆盖。

课程营销模块只保存用户方法与图片结构的抽象提炼，不复制原图片、参考课程名称、示例品牌、原句、用户档案或会员数据。公开仓库另提供 `packaging/test_remote_install.py`，用于推送后按登记表在临时项目核对本次 Skill 集合与菜单，以及包更新脚本的文件事务测试。本地合成教练档案、行为冒烟脚本和详细验证记录不属于学员安装必需文件；未单独确认公开前留在维护者工作区，不因发布运行包而一并推送。

每日热点模块的运行白名单仅为 `yetong-timer/SKILL.md`、`yetong-timer/agents/openai.yaml`、`yetong-timer/references/LICENSE`、`yetong-timer/references/hotspot-method.md`、`yetong-timer/references/scheduling.md`、`yetong-timer/scripts/check_profile.py`。真实人物 DNA、任务执行结果、任务标识与本地回归记录不进入公开运行包；只保存方法与环境核实规则，不把私人档案全文嵌入 Skill。静态校验不能证明后台定时执行、手机云端持久注册或真实热点筛选质量。

全新安装的封面目录只含原版接入资源；从旧安装更新时，更新器为保留未知文件可能留下旧参考作为非运行历史。新入口和登记表明确不引用旧方法，不能为清理这些文件而擅自删除学员的其他资料。本地预览的安装验收不等于远端已推送；本轮原版替换需另行同步后才会被 GitHub 更新模块获取。

本包是可检查的本地文件封装，不是公开安装器。先前合成档案冒烟跑通过主入口 → 选题 → 文案、主入口 → 内容体检、主入口 → 标题、主入口 → 封面，以及未激活拦截；封面模块还测过缺本人照片、会员照片无授权、无依据效果保证和跨教练留出样本。这些旧名阶段的证据不能替代短名版的重新回归；远端 `npx` 安装也需按推送后的仓库版本另行验收。真实图片生成和手机云端 Agent 仍未验证。MIT 许可证和框架地图公开权限已由用户确认；不要把隔离测试当作跨教练真人或获客效果验证。

## 已有证据与剩余边界

- 已有叶童本人档案的真实选题、文案与语气反馈；旧版主入口用其已激活档案做过非盲行为冒烟。新增体检模块目前只用合成 active／draft 档案做过行为测试，未用叶童本人或第二位教练做真实内容体检。
- 新增标题模块不含 DBS 的标题公式库、旧例或“验证过的爆款”主张；它以本地会员问题、本人证据和正文承诺决定标题。合成档案验证结果见本地标题验证记录。
- 封面模块现按用户要求纳入个人原版工作流及两份视觉／构图参考，不再执行先前自行提炼的五类封面方法。原版的产品选项保留，可在简短说明中用真实器械、训练计划本等解释本地健身语境，但不改选项或补造品牌细节。个人照片、档案和会员素材仍不复制；旧版合成行为记录不能替代本次原版接入后的测试，实际图片生成和肖像授权仍须逐次核对。
- 六组一次性访谈支持语音转录，新增资料供内容各阶段按需取用；结构检查、合成输入和旧档案兼容检查不等于真实语音识别或另一位教练的耗时验证。
- 课程朋友圈模块新增后须重新检验本地安装、主入口分流与计划接续；用户提供的方法、图片及合成素材测试不证明真实营销收益。本轮先本地制作，不因已有 GitHub 仓库而默认推送、发布或全局安装。
- 每日热点模块新增后须重验主入口分流、本人 DNA 门槛、固定 3 题、真实热点核实与原生调度缺失时的行为；本轮不创建真实任务，因此不能报告后台任务已成功，也不能把本地 Skill 交付或回归当作豆包／WorkBuddy 手机云端实测。
- 第二位真人教练试用不是当前本地封装的验收条件；这也意味着尚不能声称跨教练个性化效果已获真人验证。
- 不把用户给出的爆款元素概率或播放量数字当作保证，不承诺会员训练结果、内容播放量或到店成交。
