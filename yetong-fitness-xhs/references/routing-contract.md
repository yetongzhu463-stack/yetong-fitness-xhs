# 本地会员内容路由与交接契约

本入口只服务“健身教练在所在地获得线下会员”。[能力登记表](capability-registry.json) 是可用模块、入口及前置条件的唯一清单；本文件说明跨模块的选择规则，并保留当前三个模块的回归样例。新增模块须先登记和校验，不靠搜索未登记目录来扩展能力。每位教练使用自己的已激活人物档案，不把某位教练的城市、经历、产品或文风写成全体默认值。

## 通用选择顺序

1. 先确认教练身份与本地线下会员目标。教同行获客或全国线上招生不路由；同时出现两位教练时先确认对象。
2. 从本人档案读取真实服务区域、客群和产品。用户改选另一项本地产品／服务时，先确认它在档案中且仍真实可提供，再依据登记项的 `offer_fit` 匹配；不能把叶童的女子减脂业务当作全体默认值。
3. 候选项要求 `active` 档案时，用其声明的 `profile_check` 核验本人档案。`optional` 模块可处理没有个人事实的通用任务，但要使用本人城市、经历、产品或表达时同样先核验 active。无档案、未激活或结构无效时，不得个性化；对个性化请求显示固定提示并转到产出 `active_profile` 的模块，只缺明确路径时只问路径。
4. 结合登记项的 `purpose`、`use_when`、`avoid_when` 和 `required_any_of`，优先选择能完成用户当前结果且前置条件已满足的模块。多个模块同样适配时才参考 `priority`，不得仅凭关键词或排序数字决定。
5. 需要连续阶段时按前置关系执行；候选题尚未由用户选定，或按其明确授权代选前，不能把它当最终题写稿。没有已登记模块可完成的目标，应说明目前尚未覆盖。

## 当前三个模块的回归样例

| 档案与当前材料 | 用户要的结果 | 路由 | 最小动作 |
| --- | --- | --- | --- |
| 没有档案，或 `draft`、`pending_confirmation`、`needs_review`、路径失效、结构无效 | 要个性化内容 | 登记表中产出 `active_profile` 的模块 | 先显示固定未激活提示；继续访谈或修复，不擅自设为 `active`。 |
| 已有档案 | 要访谈、改城市、服务客群、经历或公开权限 | `yetong-fitness-xhs-profile` | 从既有内容继续，重大变化重新确认。 |
| `active`，没有确定选题，只有“今天发什么”“减脂想写点内容”等宽泛方向 | 要内容方向或说想写一篇 | `yetong-fitness-xhs-topic` | 先从本地客群问题、人物证据出具体候选，不直接成稿。 |
| `active`，已有多个候选题或想比较角度 | 要选择题目 | `yetong-fitness-xhs-topic` | 筛题并推荐优先项，不把未选题当作成稿输入。 |
| `active`，一个具体的本地会员问题／已选角度 | 要完整单篇文案 | `yetong-fitness-xhs-copy` | 交接这个问题和证据链；具体问题不要求先拟好正式标题。 |
| `active`，已有一篇草稿 | 要改稿 | `yetong-fitness-xhs-copy` | 核对事实、文风与公开权限后改本篇，不重新出题。 |
| 用户说“建过档”，但本轮和上下文都没有明确路径 | 要个性化内容 | 暂停路由 | 只追问档案路径，不扫描私人目录或假设激活。 |
| 明确要求教同行获客或全国线上招生 | 任意 | 范围外 | 说明这套 Skill 只服务本地线下会员，不把范围外业务改写成本地获客请求。 |

## 新模块接入契约

维护者可在自己的环境制作新 Skill；制作工具本身不属于运行依赖，也不进入发布包。新模块应先按其实际能力填写 `capability-registry.json`：唯一 id 与同名 `SKILL.md` 入口、逐项批准的 `package_files`、用途、适用和排除情境、档案要求、必要输入、产出、与教练本地产品的适配描述、自己的预检脚本（若需 active 或 optional 档案）、优先级及启用状态。运行主入口的 `scripts/validate_registry.py` 后，再测试直接／间接请求、缺档案或关键输入、相邻但不应命中的请求、与既有模块的竞争、同主题延展和跨教练隔离。

登记校验只证明结构，不证明路由行为或内容质量。安装环境更新模块后还应重新加载可发现的 Skill 列表；主入口不能假装一个尚未安装或未交付的模块可用。

## 消歧规则

1. 先看素材成熟度，再看动词。“帮我写减脂”仍是宽泛方向；“写一篇回答本地会员担心买课后服务会变的笔记”已经是一个具体问题。前者先选题，后者可直接写稿。
2. 同时要求“给题再写稿”时按选题 → 文案顺序执行。用户须选题；只有用户明确说“你从候选里选最合适的一题直接写”，才可由系统代选，并说明选择依据。
3. 有现成草稿且说“帮我改顺”时走文案；若只要求发布风险检查、标题公式或封面设计，则不冒充这三个下游 Skill。
4. 当前会话新说法和档案冲突，或用户指定的教练与档案身份不一致：不静默选择。交回人物访谈核对，或只问本次用哪份档案。不得把 A 城市、A 的会员故事写给 B 教练。
5. 内容类型的人设型、营销型、利他型、流量互动型由选题 Skill 标注；文案 Skill 可依据已选题和真实资料选主类与子类。主入口不自行重定义分类。
6. “再出 5 个选题”等承接型短请求，继承最近已完成的具体题或稿件的核心主张，并在任务卡里注明“同主题延展”；不要丢弃上下文当成全新选题池。用户明确说“换个方向”时才清空这一主题约束。若上下文没有可靠的具体主题，则按档案做常规选题。

## 下游交接最小包

只交接本次所需，不复制档案全文：

```text
固定目标：该教练服务范围内的本地线下会员
人物档案：用户指定或本会话已交接的路径；profile_id／display_name；核验结果
当前能力：从登记表选中的模块 id 与所需前置输入
本地内容依据：真实城市及到店区域；客群片段；具体顾虑和来源；本人的产品、经历／服务动作／证据
已选题：具体问题与角度、工作标题、主内容类型、筛选理由；若无则标记未选
事实边界：已确认可公开、待确认、仅内部使用、禁止公开；条件性做法与已发生个案分开
本轮要求：数量、形式、目标人群或已有稿件（若有）
承接关系：同主题延展及其上一主题／明确换方向／无可靠上一主题
```

目标 Skill 仍须自行读取同一个 `person-dna.md`，复核其规则。主入口的预检不替代下游的事实与权限检查。
