# 人物档案读取契约

本 Skill 只读用户明确交给本次任务的 `person-dna.md`。档案本身是私有真源，不是本 Skill 的资源文件，也不随 Skill 发布。

## 前置检查

1. 运行 `scripts/check_profile.py <path>`。退出码为 0 且输出以 `active:` 开头，才进入个性化选题；脚本当前不输出 `status=active` 字样。
2. 前置脚本仅核对可读性、frontmatter、状态及关键章节。它不证明访谈事实、授权或服务承诺真实。
3. 再按档案中每一条信息的来源、确认状态、公开级别和适用时间判断能否用于选题。
4. 当前对话与档案冲突时，指出冲突并请用户核对；不得静默选择一边。重大身份、城市或业务变化应回人物底色访谈更新档案。

旧版 `schema_version: 2` 且已激活的有效档案继续通过原有门槛；六组访谈新增信息属于内容补充，不构成重新激活的条件。信息未提供时保留未知，当前任务能用既有事实完成就继续，仅在缺口影响本题真实性或本地受众判断时补一个必要问题。

## 六组资料如何进入选题

| 建档资料 | 本题可取的真实依据 | 使用条件 |
| --- | --- | --- |
| 业务定位与一句话场馆优势 | 已确认城市、服务范围、环境／器械特点、场馆实际服务 | “环境好”等本人判断需落到可展示细节；不升级为当地最好 |
| 到店会员与最多服务的人群 | 最常服务的群体、真实表面目标、平台期／反复／饮食／信任等实际阻碍、到店约束 | 宝妈、女性等标签与痛点举例只是提问提示；以本人回答为准，不从标签补造需求 |
| 客户问题与处理 | 会员原话、发生情境、教练实际怎么做 | 把提问与已发生行动、条件性处理分开 |
| 你是谁、资质、优势与交付 | 称呼、角色、年限、专业优势、课程标准、课外及饮食服务的实际方法／频率 | 证书名与资格范围须核对；有饮食指导不等于每天监督 |
| 高光经历与匿名最佳案例 | 可公开的职业选择、本人贡献、服务动作、获授权的个体变化 | 三件高光是素材池，不要求每题全部出现；匿名案例的数字、照片、聊天各核对许可 |
| 为什么选择你 | 本人概括的核心优势及其支持事实 | 自述“客户选择我因为……”不能冒充会员评价或所有客户共同原因 |

先取“主要本地客群的一个真实目标／阻碍”，再选能回应它的一项场馆、个人或交付证据。证书不自动证明训练结果，高光案例不代表其他会员也会达到同样效果。

## 内容使用级别

- `已确认 + 可公开`：可成为工作标题和公开场景，仍需避免夸大结果。
- `已确认 + 需再次确认`：可作内部筛选依据，不直接写成拟发布的事实断言。
- `仅内部使用`：只影响判断，不能在建议公开的标题或画面中泄露。
- `禁止使用`：不得使用，也不得借组合信息暗示。
- `待确认`、未给出来源或已失效：不能写成当前事实。必要时只列作“待补素材”。

会员授权逐项判断：匿名数字不等于照片、姓名、聊天记录或健康细节的公开许可。对非常具体的本地场馆与会员变化数据，考虑反向识别。

## 内部映射

每次个性化结果必须能追溯：

```markdown
使用的人物信息：
使用的本地客群信息及来源：
未使用的待核实信息：
公开边界检查：通过／待核对
```

若用户仅要求看选题列表，展示可压缩，但不能删掉“待核对”的关键提示。
