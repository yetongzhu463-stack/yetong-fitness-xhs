# 人物档案读取契约

本 Skill 只读用户明确交给本次任务的 `person-dna.md`。档案本身是私有真源，不是本 Skill 的资源文件，也不随 Skill 发布。

## 前置检查

1. 运行 `scripts/check_profile.py <path>`。退出码为 0 且输出以 `active:` 开头，才进入个性化选题；脚本当前不输出 `status=active` 字样。
2. 前置脚本仅核对可读性、frontmatter、状态及关键章节。它不证明访谈事实、授权或服务承诺真实。
3. 再按档案中每一条信息的来源、确认状态、公开级别和适用时间判断能否用于选题。
4. 当前对话与档案冲突时，指出冲突并请用户核对；不得静默选择一边。重大身份、城市或业务变化应回人物底色访谈更新档案。

## 内容使用级别

- `已确认 + 可公开`：可成为工作标题和公开场景，仍需避免夸大结果。
- `已确认 + 需再次确认`：可作内部筛选依据，不直接写成拟发布的事实断言。
- `仅内部使用`：只影响判断，不能在建议公开的标题或画面中泄露。
- `禁止使用`：不得使用，也不得借组合信息暗示。
- `待确认`、未给出来源或已失效：不能写成当前事实。必要时只列作“待补素材”。

会员授权逐项判断：匿名数字不等于照片、姓名、聊天记录或健康细节的公开许可。对非常具体的本地场馆与会员变化数据，考虑反向识别。

## 内部映射

每次个性化结果必须能追溯：

```markdown
使用的人物信息：
使用的本地客群信息及来源：
未使用的待核实信息：
公开边界检查：通过／待核对
```

若用户仅要求看选题列表，展示可压缩，但不能删掉“待核对”的关键提示。
