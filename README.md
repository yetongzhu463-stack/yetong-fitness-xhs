# YETONG｜本地健身教练技能组

YETONG 面向**主要服务本地线下会员**的健身教练。当前已交付小红书内容创作流程：先建立经本人确认的人物档案，再围绕所在地的会员顾虑做选题、文案、标题、内容体检和封面方案。它不教同行获客，不面向全国线上招生，也不承诺播放量、咨询量或训练效果。

项目采用 [MIT 许可证](LICENSE)，作者已同意公开本项目自行提炼的内容框架地图。原课程 PDF 及右侧完整示例文案不在项目或许可证范围内。

## 三条服务线

- **小红书内容创作｜当前可用。** 叶童将一线服务会员与内容运营的经验提炼为可重复执行的判断流程。据叶童提供的口径，方法来自约五年的实践及近 2,000 篇内容的创作与复盘；本开源包保存的是提炼后的方法和结构，**不包含近 2,000 篇案例全文**，也不把经验数字当成获客保证。
- **朋友圈营销｜规划中。** 计划围绕教练本人的经历、真实服务和客户顾虑，建立持续可信的朋友圈表达节奏；目前没有可调用的朋友圈专项 Skill。
- **业绩管理｜规划中。** 计划把线下健身业务问题拆成可核对的环节、下一步动作和复盘指标；目前没有可调用的业绩管理专项 Skill。

完整介绍见[三大类技能目录](docs/SKILL_CATALOG.md)。`yetong` 主入口与 `yetong-dna` 人物档案是共用基础，不另算一条服务线。介绍规划方向不代表相关 Skill 已安装或可运行。

## 当前八个 Skill

- [`yetong`](yetong/SKILL.md)：主入口，按需求和材料状态选择已登记、可读取的模块。
- [`yetong-dna`](yetong-dna/SKILL.md)：用短访谈建立、确认和更新教练本人的人物 DNA。
- [`yetong-topic`](yetong-topic/SKILL.md)：把本地会员顾虑与本人真实素材转为选题，并标注四大内容类型。
- [`yetong-copy`](yetong-copy/SKILL.md)：根据已选题、本人资料和四类内容框架写单篇稿或改稿。
- [`yetong-review`](yetong-review/SKILL.md)：体检具体选题或草稿，指出最值得先改的地方，不自动重写。
- [`yetong-title`](yetong-title/SKILL.md)：为具体本地会员问题或正文拟定、比较与优化标题。
- [`yetong-cover`](yetong-cover/SKILL.md)：为已定选题或稿件设计封面构图、实拍清单和提示词；条件满足时可接续生成图片，默认不擅自生图。
- [`yetong-update`](yetong-update/SKILL.md)：检查版本或更新当前安装的官方技能包，核验资源并保留人物档案和其他技能；不要求先建档。

八个 Skill 应一起提供。主入口从[能力登记表](yetong/references/capability-registry.json)读取可用模块；新增模块需先登记、验证并加入发布清单，学员更新后才可调用，仅放入目录不会自动生效。DBS Skill Maker 可以作为维护者自己的制作工具，但不是使用本技能组的前置依赖，也不在运行包中。体检、标题、封面与更新模块均独立编写，不包含 DBS 或原个人科技封面 Skill 的原文、案例与专属形象。

这次缩短的是 **Skill 调用名**，不是 GitHub 仓库地址。旧调用名不会自动改写成新名；更新后如果 Agent 同时列出新旧两组，请先按下文检查八个短名均可用，再自行核对并处理旧目录。不要在未确认新包完整安装前删除旧版，也不要清理人物档案。

## 安装

需要 Node.js／`npx` 和能运行 Python 3.9 或更新版本的 Agent 环境。以下命令只安装 GitHub 上**已推送**的版本；本地改名或新增模块在推送前不会出现在远端安装结果中：

```bash
npx -y skills add yetongzhu463-stack/yetong-fitness-xhs -g --all
```

`-g --all` 会尝试安装到安装器所支持的 Agent 的全局 Skill 目录；具体手机云端 Agent 是否允许执行命令、是否持久保存 Skill，取决于该平台，不能仅凭安装指令保证。若只想安装到 Codex，可运行：

```bash
npx -y skills add yetongzhu463-stack/yetong-fitness-xhs -g -a codex --skill '*' -y
```

若是在支持执行安装任务的 Agent 对话中，可以直接发送一句话：

> 请从 GitHub 仓库 `yetongzhu463-stack/yetong-fitness-xhs` 安装全部 YETONG Skill；安装后按当前能力登记表逐个核对 `SKILL.md` 和必要资源，再调用 `yetong` 展示三类菜单。若当前环境不支持安装或不能持久保存，请直接说明，不要把读到仓库页面当作安装成功。

这句话是**安装与验收请求**，不是所有平台通用的安装接口。[skills CLI 的 Agent 支持清单](https://www.skills.sh/agent)未列豆包或 WorkBuddy。豆包普通手机端是否能导入第三方 GitHub Skill，尚无可据的官方保证；[火山引擎 AgentKit 的 Skill 能力](https://docs.volcengine.com/docs/agentkit/create_skills?lang=zh)也不等于豆包 App 已开放同一安装方式。WorkBuddy [桌面端支持上传本地技能包](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)；[手机连接电脑模式](https://www.workbuddy.cn/docs/workbuddyapp/features/Multidevice)可调用电脑上已启用的技能，而[独立云端任务使用独立的云端技能库](https://cloud.tencent.com/document/product/1831/138797)。本仓库尚未在豆包手机云端或 WorkBuddy 云端完成实机安装验证。

## 首次使用

**安装动作本身不能保证 Agent 自动弹出欢迎介绍。** 八个 Skill 实际可读取后，打开新对话并发送下面这句话；Codex 中也可显式调用 `$yetong`：

> 使用 `yetong`，展示当前实际已安装的 YETONG 全部技能，按“小红书内容创作、朋友圈营销、业绩管理”三类介绍每项能做什么、怎么触发；已开发但本机缺失的标“未安装”，尚未开发的标“规划中”。然后告诉我第一步该做什么。

若 Agent 只能描述本页文字，却无法读取相应 Skill 和能力登记表，不应认定整包已经安装成功。主入口的 `scripts/show_menu.py` 会校验七个短名；校验失败应说明缺少什么，不应把规划中的两条服务线说成已上线。更完整的新手说明见[第一次使用 YETONG](docs/START_HERE.md)。下面是建档后常用的自然语言请求：

1. 尚未建档时，说：“先帮我建立人物档案。”未提供城市时，应先问“你目前在哪个城市服务本地会员？”，再按回答了解商圈与会员；已明确说过本人的带课城市则不重复问。示例教练、测试素材、设备定位和被否定的地点不能当作你的城市。访谈先问最少的业务、客户问题和服务动作；无需一开始讲完整人生。
2. 首次保存档案时，指定一个**在 Skill 安装目录之外、仅自己可访问**的位置。档案文件名为 `person-dna.md`。教练核对事实与公开边界并明确确认后，档案才会变为 `active`。
3. 建档后，可以说：“这是我的 `person-dna.md` 路径：〔实际路径〕。我今天不知道发什么，帮我找面向本地会员的选题。”有具体问题时也可以直接说：“我确定写〔会员真实顾虑〕，帮我写一篇。”
4. 需要更新城市、服务、产品或公开权限时，先改同一份档案并重新确认受影响的内容，再继续出题或写稿。
5. 已有选题或草稿但不想立刻重写时，说：“用我的已激活人物档案，先体检这篇内容，告诉我最该改的 1–3 处。”
6. 已有具体选题或稿件、只想改标题时，说：“这篇回答〔本地会员的具体问题〕，请按我的档案给几个标题并推荐一个，不要写正文。”
7. 已选定具体选题或写好草稿、想做封面时，说：“这是我的已激活档案路径和本篇选题／草稿。请做适合我本地会员的封面方案与实拍清单。”若给出了完整成图指令、当前 Agent 有生图能力且素材与授权齐备，Skill 会问“直接生成”还是“继续优化提示词”。只给无字底图提示词不等于已经有可发布封面；回复“直接生成”后仍须核对文字与画面。没有本人照片时，不会生成陌生人的脸冒充教练。

主入口不会搜索私人目录猜档案位置。没有已激活档案时，不能生成声称“像这位教练本人”的个性化内容；用户明确要求通用版本时，也不得套用别人的经历、城市或口吻。

## 以后怎么更新

已安装 `yetong-update` 后，直接说“更新叶童技能”；在 YETONG 主入口任务中也可以只说“更新”。只想知道有没有新版，说“检查叶童技能更新”，它会只检查版本。人物档案、城市或文案里的“更新”仍归相应模块处理。

更新模块读取本仓库 `main` 的发布清单，从固定提交下载已登记运行文件，核对哈希后更新**当前这一套安装**。新增的已登记技能随清单一起加入；包外人物档案、其他作者技能和未受管文件保留。更新前保留备份，失败时恢复本次改动。成功后新建一次对话，再让主入口检查菜单。它不会顺便更新其他技能包，也不自动扩大到另一台设备或另一套 Agent 安装。

旧七技能版没有此模块，需要先重新运行上面的原安装命令一次。安装方式由平台管理、不能执行 Python、不能联网或没有持久可写 Skill 目录时，更新模块会说明实际限制并给出平台导入步骤，不能保证豆包／WorkBuddy 云端一句话持久更新。

维护者每次新增或修改技能后，依次运行 `python3 packaging/build_release_manifest.py`、`python3 packaging/build_release_manifest.py --check`、相关校验与打包，再将运行文件和发布清单一起推送到现有 GitHub 仓库。更新清单不包含私人档案或课程 PDF。

## 发布与资料边界

MIT 允许使用、修改、分发和商业复用，但再分发时须保留版权和许可证声明。每个 Skill 的 `references/LICENSE` 都随其目录一起安装，以便单独安装后仍附有授权文本。

人物档案、会员记录、原课程 PDF、真人试稿和开发评测不属于可分发文件。会员姓名、照片、聊天记录与健康信息应分别取得相应公开授权；匿名数据也需要检查小城市和场馆信息组合后的反向识别风险。课程权益、价格和效果数字在具体发布前仍需核对原始依据。

本地结构、行为冒烟与隔离安装测试不等于跨平台运行或另一位教练的真人验证。GitHub 上的实际版本以远端提交、发布清单和安装后的实际短名校验为准，不能只因 README 描述更新就认定手机端已安装。任何测试都不承诺实际流量、咨询或成交结果。
