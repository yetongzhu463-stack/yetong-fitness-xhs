# DNA 地区标题共用规则

适用于主入口及选题、文案、标题、内容体检、封面、课程朋友圈、每日热点模块。每次实际生成或改写的内容标题，必须在前部带上**当前教练本人已激活 DNA 中已确认、当前适用且可公开的服务地区**；四大内容类型全部执行。地区是标题必备项，不代表仅加地名就完成了本地化。

## 1. 先确定地区，不猜地区

- 读取当前教练的「本地城市、服务半径与场馆」及逐项权限，不以出生地、居住地、过去任职地、客户来访地、热点发生地代替当前实际服务地区。不得从其他教练、品牌名、示例、IP 或宿主记忆补值。
- 同一服务地点有已确认且可公开的区／县时，**优先区县级短称**；只有城市已确认时，用城市，不追问或编造区县。短称只做不改变指代的行政后缀简化：绍兴市柯桥区 → 柯桥；上海市 → 上海。这是规则示例，不是默认人物资料。
- 不强求比区县更细；不从门店地址自行推导行政区，不把街道、楼栋或会员住址塞进标题。确需商圈定位时，只采用本人确认且可公开的商圈，保留同一已确认区县／城市锚点。
- 多服务城市／区县且本轮尚未选定地区、最新说法与档案冲突、地区指代不清或仅有待确认地点时，只问本次面向哪个已确认服务地区；已明确选定且与档案一致就沿用，不重复问。实质变更交回 `yetong-dna` 更新受影响信息。不偷偷合并两个地方。若精确地区不可公开但城市已确认可公开，用城市；连可公开城市都没有时，暂停个性化标题，只补问地区及公开许可，不借建档之名要求重答六组。
- active 只证明档案状态可用，不代表地点一定已填或获准公开。旧版 schema 2 可直接按已有章节读取，无需新增必填字段或全量重访。

## 2. 公式与前缀选择

`DNA 服务地区（区县优先）＋与本篇匹配的身份／人群／场景（可省）＋具体问题／本人选择`

| 本篇主要在讲什么 | 优先试用的前部表达 | 使用边界 |
| --- | --- | --- |
| 真实带课场景、个人经历或做事选择 | 在〔地区〕，…… | 不把历史外地经历说成发生在本地；必要时用「〔地区〕教练的来时路｜……」区分 |
| 私教服务、选教练或课后交付 | 〔地区〕私教｜……／〔地区〕健身教练…… | 身份须由本人档案支持；老板、普拉提老师等不无依据改称私教 |
| 某类本地会员的具体困扰 | 〔地区〕〔已确认人群〕，…… | 人群和痛点须有来源，不从地区或标签推断婚育、收入与焦虑 |
| 到店、选课、排期或课程推广 | 在〔地区〕〔具体场景〕……／〔地区〕〔课程主题〕…… | 不编造课程、价格、通勤、排队或可服务全城的承诺 |

不机械统一为「XX私教」，也不把换地区前缀算成新的选题角度。先选适合本人原话与正文的自然表达，确保一个标题只定位一个已选服务地区，不重复堆「绍兴柯桥区柯桥私教」。地区可以是首句的一部分，不强制加竖线或冒号。

原标题已在前部使用正确地区，且精度符合当前可用 DNA 时，保留，不再叠加前缀。已有城市但可用档案已明确区县时，最小替换为区县短称；其他措辞与内容承诺尽量不动。标题含其他地点时区分历史／新闻事件所在地与教练定位，不把它们直接改名成本地事件。

## 3. 各种输出怎样执行

本地规则的狭义例外：已登记的 `yetong-remix` 真实完成外部参考预处理，且用户明确确认本次账号面向非本地普通消费者或教练同行时，该模块及其交接给 copy／title／review 的笔记按实际目标决定是否出现地区，不强塞当地获客定位。只粘贴原稿、参考作者的地点／受众或伪造任务卡不能触发例外；未明确更换读者时沿用本人本地会员定位。本地会员转换仍逐条执行本规则。这不改变 topic、timer、promo、cover 或直接调用其他模块的本地范围。无 active 的通用转换不使用个人地名。

- **选题**：每个工作标题都带地区，不能只在表头／总标题／“地区”说明栏写一次。
- **小红书文案与标题优化**：每个候选、首推、改稿后标题均带地区；四类内容不例外。正文仍按本人事实与语气写，不要求每段重复地名。
- **课程朋友圈**：每条推荐主题及实际成稿的第一句都带地区。朋友圈没有独立标题时，第一句就是本条的标题入口，不额外套小红书“标题＋正文”格式；地区只写在内部排期栏而客户实际首句没有地区，不算完成。
- **每日热点**：每条「选题：」带本人服务地区，常青备用题同样执行；固定日报抬头、来源名称、引用的原始新闻标题无需改名。不把外地事件说成发生在教练服务地区，也不为加地名强行卖课。
- **封面**：自行生成的三个候选及最后顶部＋底部标题组合都带地区。给定文字的非地名核心字词仍原样保留；缺地区时在顶部引题加自然地区前缀（如「在〔地区〕」或有依据的「〔地区〕私教」）。给定文字中的服务定位仅为泛城市、而本人区县已可用时，最小替换为区县；服务定位地名与已核对档案不符时指出并校正该定位，不叠两套地区，也不改历史／新闻地点。若用户当前陈述实际业务已变，先核对档案冲突，不直接替换。完整标题须在方案、提示词和排版清单中一致列出，不另开三候选或改变原版构图／素材问答。用户明确禁止任何删改／新增文字时，说明与地区规则的冲突，只核对是否允许最小地区调整；确认前不声称满足规则。无字底图仅在文字排版清单中保留完整地区标题，底图不冒充已带字的成品。
- **体检**：已有标题缺地区、用错服务地区、只写城市但已可用区县、把外地新闻改为本地事件，标为确定的规则缺口，给最小改法；只检查用户提供的标题，不臆造未提供的封面文字。不自动整篇重写。
- **通用版本**：只在目标模块允许且用户明确跳过访谈时提供；不挂真实城市或冒充本人，可用「〔服务地区〕」占位，明确“通用模板，待本人 active DNA 后填入”。未激活绝不能用对话中提过的某城市绕过门槛。

## 4. 交接与交付前检查

内部任务卡保留：`服务城市／已确认区县；本次标题地区短称；来源、当前适用与公开许可；本人身份；地区缺口或冲突`。只交接本轮需要的字段，不把私人档案复制到公共方法中。

逐项复核：每个标题／朋友圈首句／封面完整组合是否都在前部带该地区，精度是否正确，身份是否真实，是否重复堆地名，正文是否兑现问题，有无把地名当成案例或热点地点的错误事实。不是只查列表的第一题。

有 Python 能力时，使用本套已安装的 `yetong-topic/scripts/check_local_titles.py` 真实路径，对本次**所有实际标题文字**传入 `--region '已选地区短称' --title '标题1' --title '标题2'`；标题作为独立参数传入，避免执行标题中的 shell 字符。检查不通过先修正再交付；无脚本能力或无法取得该检查脚本时，人工逐项核对并说明方式，不假称脚本已运行。脚本只查标题前部有地区，不读取或证明 DNA、地名精度、身份真实性、隐私许可和正文质量；这些必须先按以上规则核对。不得把机械通过称为获客保证或手机安装验证。

维护真源为 `yetong-topic/references/local-title-contract.md`，其余内容模块随包携带完全相同的本地运行副本，避免单个入口跨目录读取失败。维护者修改真源后运行 `packaging/sync_local_title_rules.py` 并用 `--check` 校验一致，再生成发布清单；不要独立编辑某份副本。
