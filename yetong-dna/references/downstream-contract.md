# 下游读取契约

本契约供叶童小红书主入口、选题和文案 Skill 使用。

## 读取前检查

1. 定位用户明确指定的人物档案。
2. 运行 `validate_profile.py` 或完成等价结构检查。
3. 只在 `status: active` 时启用人物 DNA 驱动。
4. `draft`、`pending_confirmation` 或 `needs_review` 均不得被描述为已激活。

## 事实使用

- 只把“已确认”信息写成事实；
- 只把有来源的本地客群痛点写成确定判断；行业常识和城市印象只能作为待验证候选；
- “待确认”信息只能形成问题或候选，不得进入成稿；
- “仅内部使用”可以影响策略判断，但不能出现在公开文本中；
- “禁止使用”的信息不得以改写、暗示或组合推断方式泄露；
- 已失效的信息只用于理解历史，不描述为当前状态。

## 个性化输出

下游每次输出至少保留一份内部映射：

```markdown
使用的人物信息：
- ...

使用的本地客群信息及来源：
- ...

需要补充的事实：
- ...

公开边界检查：通过／需要确认
```

面向用户展示时可以压缩措辞，但必须能够回答内容为什么适合这个人。

## 冲突处理

当前对话与人物档案冲突时：

1. 不静默选择任一版本；
2. 指出冲突及其可能影响；
3. 询问当前事实；
4. 重大变化把档案状态改为 `needs_review`，交回人物访谈 Skill 更新。

## 无档案或未激活

展示主 Skill 中规定的人物 DNA 未激活提示。用户明确跳过后，可以提供通用版本，但必须：

- 不调用个人经历；
- 不模仿个人口吻；
- 不编造城市、场馆、客户或故事；
- 不把全国性健身人群画像冒充为该城市的真实客群；
- 明确说明个性化能力尚未启用。
