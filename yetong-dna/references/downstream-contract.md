# 下游读取契约

本契约供 `yetong` 主入口、`yetong-topic`、`yetong-copy`、`yetong-title`、`yetong-review`、`yetong-cover` 和 `yetong-promo` 读取人物 DNA。`yetong-update` 的安装／更新工作不依赖人物档案，不等待建档或激活。

## 读取前检查

1. 定位当前教练本人明确指定的私人档案，确认身份匹配，不读取他人或演示档案来补值。
2. 运行 `validate_profile.py` 或完成等价结构检查。
3. 只在 `status: active` 时启用人物 DNA 驱动；`draft`、`pending_confirmation`、`needs_review` 均不能称已激活。
4. 保持对现有 `schema_version: 2` 和 13 章节档案的兼容。新六组访谈只增加可选细项；字段缺少、未列满三件高光或没有成功案例，不使旧档案失效。
5. 使用同一已激活档案的已确认版本；各 Skill 不复制人物档案、录音或原 PDF 到自己的可分发目录。

## 六组信息怎样进入运营场景

不要求每篇内容引用所有材料。为当前任务选取真正影响受众、观点、可信证据或表达的条目，并保留事实来源与公开级别。

| DNA 来源 | 能支持的运营内容 | 使用边界 |
| --- | --- | --- |
| 本地业务与一句话场馆优势 | 本地到店定位、场馆体验、选馆顾虑、环境／器械／团队的具体内容和合适的视觉场景 | 当前城市有本人来源；场馆优势要有实际细节，不升级成最强、唯一或排名；场馆优势不冒充教练个人优势。 |
| 最多服务群体、表面目标与深层困扰 | 按真实主要客群选择选题、标题钩子、情境和咨询障碍；结合来访地点与通勤判断本地相关性 | 未提供主要群体就用已确认到店客群，不按宝妈／女性等示例自动补人群和动机；痛点例子仅是候选。 |
| 客户原话与本人处理 | 共鸣开头、利他解释、顾虑回应、营销中的服务证据、互动提问 | 区分准确原话与转述；实际动作、频率和公开承诺分别读取，不把拟采取动作写成已完成。 |
| 当前身份、专业方向、资质和交付标准 | 人设可信度、方法解释、课程标准、训练记录、体测、课后／饮食跟进等服务场景 | 证书和能力按核实状态使用；专项名称不推导医疗资质；只采用实际标准、方法和已知频率。 |
| 高光与匿名会员案例 | 人设经历、过程故事、交付案例、对方法的具体说明 | 有几件就用几件，不凑满三件；效果值重新核算；匿名不等于获得数据、照片和聊天的公开许可。 |
| 一句话为什么选择你 | 内容定位、差异点、可信的选择理由和合适的承接 | 区分本人自我定位与真实会员评价；不能改写成会员一致评价或成交／效果保证。 |

### 各 Skill 的落地方式

- **主入口 `yetong`**：读取已确认的本地业务、主要群体和材料状态，判断先出选题、写稿、起标题、检查内容、做封面还是策划课程朋友圈。已有足够素材时直接路由，不为补齐六组所有字段反复建档。
- **选题 `yetong-topic`**：将当前教练的主要群体、真实需求／顾虑与场馆优势、客户处理动作或可公开故事结合，再选择合适的爆款元素和四类内容。没有故事时可用真实服务场景，不能造一个高光。
- **文案 `yetong-copy`**：用已选选题对应的原话、服务过程、可公开证据和表达指纹写稿；场馆与个人优势只在相关段落出现。缺少当前文章必需的频率、数据或权限时集中补问，不能复制别人的经历来补。
- **标题 `yetong-title`**：让真实客群问题和地方信息决定标题承诺的范围；标题里的身份、场馆优势、案例数字须在正文／档案中有可用依据，不借一句自我优势制造行业结论。
- **检查 `yetong-review`**：核对城市、群体、资格、服务动作与频率、案例效果及分项公开权限，并识别自我定位被写成会员评价、示例痛点被写成事实等偏移。未激活时停止个性化体检；只有用户明确跳过访谈，才给不引用个人事实的通用检查清单，不声称已完成档案一致性诊断。
- **封面 `yetong-cover`**：从该篇内容选取已确认的城市、场馆或服务场景，并在素材权限预检后执行叶童原版单题编号流程。图1必须是本人有权使用的人物参考；不露脸可用手部、背影或局部参考，缺图1就停在上传，不给无人物或非写实海报冒充原版。图2起真实器械、计划本、场馆或其他辅助素材按原版选项收集；不知道真实外观就不补造。会员照片、姓名、身体数据和聊天等按各自权限使用，不能生成假会员变化图作为证据。DNA 不是本人照片或场馆视觉参考的替代，给定封面文字原样保留，不自动改笔记发布标题。

- **课程朋友圈 `yetong-promo`**：用本人的真实城市、主力客群痛点、服务标准、可公开证据与表达指纹，结合独立产品资料卡梳理人群、购买理由、顾虑及每日推广。产品卡记录草案／已确认／失效状态；新课程不因 DNA 未收录而强制重访，只有本人身份、业务能力或公开承诺实质冲突才回档案。草案可内部策划，不虚写已在售；对外文案须以已确认、真实可交付的课程事实为依据。不能把其他课程或历史案例的价格、权益、效果、成交及频率自动复制给新课程，匿名素材仍分别检查公开授权。

## 事实使用

- 只有「已确认」且获准公开的信息能作为公开事实；当前档案激活不等于所有条目可公开。
- 有来源的客群痛点才能写成确定判断；行业常识、城市印象和问卷例子只作为待验证候选。
- 「待确认」信息只能形成问题或候选，不进入成稿；「已失效」信息只理解历史，不描述为当前状态。
- 「仅内部使用」可以影响策略但不能进入公开文字／图片；「禁止使用」不通过改写、暗示或组合推断泄露。
- 服务动作要保留执行人、方法、已知频率和持续时间；未知不能补成每日、每课或每位会员享有。
- 场馆优势、个人核心优势和会员评价按来源分别表达，证书、资质、训练效果不互相推导。

## 个性化输出的来源映射

每次个性化输出保留简短、可检查的映射，不公开私人档案全文：

```markdown
使用的人物信息及来源：
- ...

使用的本地客群／服务场景及来源：
- ...

当前任务需要补充的事实：
- ...

公开边界检查：通过／需要确认
```

可以在面向用户的交付中压缩措辞，但须能解释为什么适合当前教练。未知或当前任务不需要的字段保留在档案，不为展示「个性化」把六组所有答案挤进一篇稿。

## 冲突与修正

当前对话与档案冲突时不静默选择版本。先核对影响当前任务的事实；本人否定的城市等未确认假设立即移除，不能继续使用。重大身份、业务或公开范围变化交回 `yetong-dna` 并将相关档案标为 `needs_review`；轻微新增事实按本人确认后更新版本，不重做整个访谈。

## 无档案或未激活

个性化任务展示主 Skill 规定的人物 DNA 未激活提示。用户明确跳过后是否提供通用版本，按目标模块规定，不绕过其门槛；允许的通用版本不得调用个人经历、模仿个人口吻、编造城市、场馆、客户或故事，也不把行业画像冒充本地真实客群，须明确个性化能力尚未启用。

一般使用说明、技能目录和 `yetong-update` 不要求先激活档案。个性化选题、文案、标题、内容体检、封面和课程朋友圈均执行各模块的激活门槛；通用版本按目标模块自己的条件提供，不以本契约绕过登记表或下游规则。
