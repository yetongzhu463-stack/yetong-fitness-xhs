# 建库与收录

## 共同读取边界

读取根级和主要目录的导航、README、项目规则；再按任务下钻。排除 `.git/`、依赖、缓存、构建、回收、明确历史备份及敏感目录。大型二进制默认只看文件名、类型、大小和位置；任务需要解析时使用现有工具，解析失败说明缺口。

区分原始资料、汇总、派生结果和历史版本。不要凭文件名猜用途或权威。方法依据：来源溯源与分层信息架构。

## 建立

1. 识别空目录、有资料无导航、有导航三种状态。已有导航时优先复用，不重建。
2. 空目录提出或按已有授权创建最小结构：`00-待整理/`、`SOURCE_OF_TRUTH.md` 和当前宿主需要的最小入口；用途已知再增加少量业务目录，不大量预建。
3. 有资料时先给领域、目录职责、候选当前版本与冲突、建议入口、排除项。把这份审计与具体变更范围对齐；用户已授权建立导航及必要入口时可在范围内继续，不额外移动原件。
4. 有归属或版本决定缺失时只问该决定；其余可以先标为待确认并交付不依赖它的部分。
5. 生成导航，必要时复用或创建局部索引。路径相对知识库根目录；局部索引中的路径相对该索引所在目录。
6. 现有项目入口修改前，先将其复制为授权范围内的实际备份文件并核对内容，不能仅在日志保存旧文。入口规则保留原文，只补“何时先读导航、读相关原文、按规则处理冲突、回答说明依据”。当前宿主机制未知时说明验证缺口，不写未核实的自动兼容承诺。
7. 验证真实路径、职责、版本依据和当前调用路径，交首次使用示例。

## 导航的实际信息要求

导航是信息类别和主题入口，不是全量文件表。至少包含：

| 部分 | 必须说清 |
|---|---|
| 快速查找 | 要找什么、到哪里、范围／业务时效／待确认状态 |
| 目录职责 | 放什么，与相邻目录的边界 |
| 版本与冲突规则 | 现有证据支持的当前版本，无法判断时的处理 |
| 维护规则 | 哪些权威来源、职责、版本关系或高频入口变化需要更新 |

一个项目默认一个顶层主入口。大量同类资料登记目录、局部索引或命名规则；高频必达的少量文件可以直达。

局部 README 至少包含用途、当前入口、原始资料位置、历史版本规则和待确认项。已有等价索引直接复用。

## 收录

1. 读取导航和候选目录索引；判断资料类型、来源、业务日期、当前状态和候选归属。
2. 检查目标同名、相似版本及已有当前版本；内容相似不意味着可以删除任意一份。
3. 给出目标路径与理由。外部文件默认建议复制保留原件；用户明确要求移动时遵守其要求及范围。
4. 当前指令已经明确源、目标、动作且无未决影响时直接执行必要检查并收录；未明确的部分先补齐，不能把“建议复制”当作复制授权。
5. 同名不覆盖，按日期、版本或来源区分名称，并核对实际内容，不能只给旧名加“最新版”。
6. 归属未知但不影响使用时进入 `00-待整理/`，标明尚未判断，不替它指定业务权威。
7. 新文件改变权威来源、目录职责、版本关系或高频入口时更新导航；普通附件仅更新必要的局部索引。
8. 报告实际保存路径、原件处理和导航变化，检查没有覆盖或附带移动。

## 完成条件

建库：导航实际存在，路径可达，职责和版本有依据，当前 Agent 有一条已核验的使用路径，用户有真实示例。

收录：目标存在且原件处理符合授权，无同名覆盖，必要导航关系已更新。无法确认的业务状态仍保持待确认。
