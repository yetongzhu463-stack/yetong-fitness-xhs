# 本地会员内容路由与交接契约

本入口的业务内容服务健身教练所在地的本地线下潜在会员，允许通过泛曝光建立专业信任，不要求每题强卖课；另有不依赖人物档案的包内更新、知识库与通用中文写作能力。[能力登记表](capability-registry.json) 同时标出三条服务线的交付状态，以及实际可用模块、入口和前置条件。当前已交付小红书内容创作（含每日热点选题），以及朋友圈中的具体课程产品营销策划与计划内文案；泛朋友圈人设／日常运营未覆盖，业绩管理仍在规划。每日热点选题属于内容线，不构成第四类或通用任意任务服务；抖音等平台只是热点来源，不因此把输出改成教同行获客。服务线 `active` 不等于线内任意场景可用。新增模块须先登记、验证并加入发布清单，学员更新后才能接入。每位教练使用自己的已激活人物档案，不把某位教练的城市、经历、产品或文风写成全体默认值。

## 通用选择顺序

优先核对用户是在维护 Skill 本身还是执行业务，不把引用材料自动当运行授权。共用目录任务交给 `yetong-zhishiku`，只在明确范围按授权建库、查原文、收录或维护导航，不要求 DNA；受管长期记忆库仍走其专门协议，不按普通知识库改写。只读不自动治理。

通用中文写作、改语气、去模型腔、短文或授权虚构交给 `yetong-xiezuo-huoren`，按本轮作者、读者、文体、篇幅和改写幅度工作，不强加教练身份或 DNA。专项本地小红书成稿仍走 copy，外部参考转小红书仍先 remix，课程营销仍先 promo；写作感可以处理明确要求的语言层，不补造业务事实、不改变原有门槛。查资料再写稿时，先知识库给原文和版本边界，再写作；不把导航摘要当证据。

新封面只使用 `yetong-fengmian-iuiu`，旧 `yetong-cover` 已退役。按正文、已确认选题或至少 3 条可公开事实建信息地图、选证据载体，再交 3:4 提示词、准确叠字和自检；无需先建 DNA。缺内容只补内容；方案无照片可用占位，要本人直接出图却缺照片则先补图 1。固定主标题不改，地域只采用用户明确可公开范围作辅助锚点。用户明确不要人物可用信息载体主视觉。仅明确请求生成并且必要事实、素材、工具齐备才出图，生成后逐字检视。接续保留同一事实与标题，只修未通过层，不走旧编号题。连续两次中文字仍不准确时交底图和叠字清单，标明未完成文字发布验收。

已提供事件的选角先进入 `yetong-stasis-angle`，优先于下文本地业务、档案与地区门槛。该阶段登记为 `profile_requirement: none`，只分析所给事件及证据，保留本次明确身份与受众；身份不是档案已激活或事实已独立核实的证明。明确用事件法但没有事件时，只问一个事件问题，不转泛选题或人物访谈。仅分享材料先问用途，解释／检查／修改 Skill 则保持原任务。只要完整稿、标题或现成稿体检时仍走对应模块。无合格候选交付缺口，不强凑主角度。标题方向和开头是分析方案，不是面向本地会员的正式发布标题，不强塞服务地区；继续成稿前必须已有用户选定或明确代选授权，并重新满足下游原有范围、active DNA、地区与公开权限。此交接不触发 remix 的读者例外。

外部参考稿转换是下文默认本地业务的狭义例外：用户明确要求用实际可读外部文字重创小红书笔记时，先进入 `yetong-remix`，不要直接进 copy。读者来自本次明确账号／本人资料，不来自作者或教练职业。仅此转换及已核实下游交接可以面向非本地消费者／教练同行，既有出题、热点、课程朋友圈等范围不扩展。默认仍是本人本地会员，标题带已确认可公开区县／城市；明确非本地读者按地区规则例外，不硬塞地区或卖课。无 active 只能 optional 通用版，不使用个人事实；已有档案缺路径只问位置，不重做访谈。该分流优先于下文通用顺序中的范围排除和自动回访。

1. 先确认教练身份与本地线下会员目标。教同行获客或全国线上招生不路由；同时出现两位教练时先确认对象。若要求“展示技能／安装检查”，先运行 `scripts/show_menu.py`，不要求人物档案。若请求仅属于状态为 `planned` 的服务线，说明尚未交付，不以内容模块代替。
2. 从本人档案读取真实服务区域、客群和业务能力，再依据登记项的 `offer_fit` 匹配。新课程可以由用户自己构造，另设产品资料卡记录草案／已确认／失效状态，不因同一本地业务中的新课程未写进 DNA 就要求整份重建。内部策划可用明确标记的草案；对外成稿需要已确认真实可交付的产品事实。若与本人身份、服务区域、业务能力或公开承诺实质矛盾才回人物模块核对，不能把叶童的女子减脂或旧课程权益当作全体默认值。
3. 候选项要求 `active` 档案时，用其声明的 `profile_check` 核验本人档案。`optional` 模块可处理没有个人事实的通用任务，但要使用本人城市、经历、产品或表达时同样先核验 active。无档案、未激活或结构无效时，不得个性化；对个性化请求显示固定提示并转到产出 `active_profile` 的模块，只缺明确路径时只问路径。
4. 结合登记项的 `purpose`、`use_when`、`avoid_when` 和 `required_any_of`，优先选择能完成用户当前结果且前置条件已满足的模块。`required_any_of` 为空不要求已选题或草稿，仍须满足档案和目标模块的运行条件。多个模块同样适配时才参考 `priority`，不得仅凭关键词或排序数字决定。
5. 需要连续阶段时按前置关系执行；候选题尚未由用户选定，或按其明确授权代选前，不能把它当最终题写稿。没有已登记模块可完成的目标，应说明目前尚未覆盖。

## 新模块接入契约

每个模块在自身 `SKILL.md` 的 frontmatter 声明唯一的 `metadata.yetong-handoff`，使用字面多行字符串。各接手行独占一行，写「接手时的状态 → 交出的东西」，最后一行写「不交出：……」。例如：

```yaml
metadata:
  yetong-handoff: |
    - 已有本模块需要的材料，要完成明确任务 → 本阶段实际交付物、关键停止点与必要限制
    - 不交出：相邻模块的职责、当前阶段不会执行的动作
```

接手字段是当前正文的摘要，不增加正文没有的能力或放宽授权。按「正文 → 接手摘要 → description」维护；同一模块可以按输入成熟度列多行，不能用一条泛化能力描述替代不同阶段。`scripts/validate_registry.py` 校验所有已启用模块的字段结构，`scripts/list_skills.py` 在核验运行文件后读取同一真源，返回 `description`、`handoff` 和真实入口供主入口选择。不在登记表另存一份 handoff，避免两个版本漂移。

主入口先匹配最终交付，再倒推缺少的前置产物；已有产物直接接续。子技能只负责其阶段，因缺材料或任务不适配需要改道时，向主入口返回当前产物、缺口和下一步所需能力，不自行扩大为另一套工作流。参考稿转换复用写稿／标题／体检、每日热点复用选题方法等正文已声明的工具依赖继续有效；它们不构成自动接入未登记技能或扩大权限的许可。

生成内容的新增模块必须继承 [DNA 地区标题共用规则](local-title-contract.md)：所有面向本地会员的实际成稿标题在前部带当前本人已确认可公开的服务地区，区县优先。主入口与直接调用均执行，不能依赖用户每轮再要求加地名。安装、更新、纯方法说明、原始新闻引用与系统日报抬头不是面向会员的内容标题，不强加地区。

维护者可在自己的环境制作新 Skill；制作工具本身不属于运行依赖，也不进入发布包。新模块应先按其实际能力填写 `capability-registry.json`：唯一 id 与同名 `SKILL.md` 入口、所属服务线、菜单名称与触发语、逐项批准的 `package_files`、用途、适用和排除情境、档案要求、必要输入、产出、与教练本地产品的适配描述、自己的预检脚本（若需 active 或 optional 档案）、优先级及启用状态。将规划服务线启用前，先交付并验证相应模块，再把状态改为 `active`；不能只修改菜单文案就宣称上线。运行主入口的 `scripts/validate_registry.py` 和 `scripts/show_menu.py` 后，再测试直接／间接请求、缺档案或关键输入、相邻但不应命中的请求、与既有模块的竞争、同主题延展和跨教练隔离。

登记校验只证明结构与声明文件存在；菜单另核对发布清单、运行文件集合与哈希。两者均不证明宿主发现／注册、实际调用、跨会话持久或内容质量。安装结果分别报告这几层证据；只有准备安装的回复不是执行结果。运行文件完整而当前宿主尚未发现时，可在真实工具支持下按文件路径读取并标为本次执行，不冒充原生注册。重新启用／刷新／新会话只按已核实的宿主规则建议，不编造接口或保证重开一定加载；持久性未核验就写未验证。

默认中文报告，原始命令与错误保留。业绩管理的服务线 id 是规划分类，不是 Skill 调用名；未覆盖的泛朋友圈场景也不是缺文件。两者不计入安装缺失项，不杜撰专项技能、不要求补装不存在的模块。

初次城市信息必须带来源。当前用户明确说过自己的服务城市时沿用；未提供时，六组一次性建档问题的第一组先问城市，再请用户按自己的城市补充区县／商圈，不从示例、他人档案、宿主地点或被否定的假设补全，不把六组默认流程拆成只问城市的一轮。居住地与带课地不一致、多个城市职责不清时，先确认实际服务会员的城市。包内更新先于档案门槛和完整登记校验；内容对象的“更新”仍归相应内容模块，不误执行软件更新。新增每日热点模块不改变此优先级。

## 消歧规则

新封面固定主标题原样保留，地区只作用户确认的辅助锚点；不继承旧封面的编号选择、强制地区改题或缺照片就禁止方案的规则。

1. 先看平台、当前产品任务与素材成熟度，再看动词。“帮我写减脂”且无课程营销上文仍是宽泛小红书方向；“写一篇回答本地会员担心买课后服务会变的笔记”已经是一个具体问题。前者先选题，后者可直接写稿。要推某门课程或承接既有课程营销计划时，“今天发什么”“接着写”“改成三天”均留在 `yetong-promo`，带着同一产品卡接续。明确要小红书笔记则回小红书路线。无产品上文、只说“朋友圈怎么发”而无法确定课程推广还是日常运营时，只问这个会改变路由的区别。
2. 同时要求“给题再写稿”时按选题 → 文案顺序执行。用户须选题；只有用户明确说“你从候选里选最合适的一题直接写”，才可由系统代选，并说明选择依据。
3. 本地小红书整稿走 copy，只看发布标题走 title，整篇诊断走 review；明确只改语言／去模型腔可走写作感并保留事实与专项门槛。封面或同一封面的“直接生成／继续优化”走新封面；保留固定标题、标签、素材与授权，先补必要缺项，不把它重新当选题。仅方案不自动生图；明确成图仍核对所需素材与工具。
4. 当前会话新说法和档案中本人身份、城市、业务能力或公开承诺实质冲突，或用户指定的教练与档案身份不一致：不静默选择。交回人物访谈核对，或只问本次用哪份档案。新产品资料卡中的草案、价格／权益调整不自动视为人物 DNA 冲突；先由课程模块核对具体课程事实。不得把 A 城市、A 的会员故事写给 B 教练。
5. 内容类型的人设型、营销型、利他型、流量互动型由选题 Skill 标注；文案 Skill 可依据已选题和真实资料选主类与子类。主入口不自行重定义分类。
6. “再出 5 个选题”等承接型短请求，继承最近已完成的具体题或稿件的核心主张，并在任务卡里注明“同主题延展”；不要丢弃上下文当成全新选题池。用户明确说“换个方向”时才清空这一主题约束。若上下文没有可靠的具体主题，则按档案做常规选题。
7. 文案与封面依赖同一内容事实时，先完成已获授权的成稿，再交新封面。优化发布标题与封面视觉同时要求时，先核对正文承诺，再交已确认文字与素材；新封面不擅自重开标题候选。
8. 创建每日热点任务、单次试跑本人热点选题和运行已注册热点任务走 `yetong-timer`，每次固定 3 题。普通“出5题”走 `yetong-topic`；课程“朋友圈每天4条计划”走 `yetong-promo`，不自动注册后台任务。每日热点任务不能因“抖音热点”而变成面向教练同行的内容，也不自动续写脚本、发布标题、封面或发布。创建前先核对同类已有任务，避免重复注册。取消或其他任务管理引导宿主原生任务列表，不要求通过本模块处理，也不将其登记为通用调度管理服务。
9. 定时创建必须绑定当前教练 active DNA、热点方法和真实可用的宿主原生调度；后台执行环境须可读取相应档案和方法。缺每日时间或时区时只补问缺项，不擅自默认 9 点或一律中国时区。豆包／WorkBuddy 原生能力须在当前环境核实，不编造创建 API 或声称手机云端已实测。只有原生调度返回可核对的任务标识、启用状态、执行时间与时区后，才能报告对应成功状态；Skill 制作、安装或一次试跑不等于后台任务已创建。
