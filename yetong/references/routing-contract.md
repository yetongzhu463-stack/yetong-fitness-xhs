# 本地会员内容路由与交接契约

本入口的业务内容服务“健身教练在所在地获得线下会员”，另有不依赖人物档案的包内更新能力。[能力登记表](capability-registry.json) 同时标出三条服务线的交付状态，以及实际可用模块、入口和前置条件。当前已交付小红书内容创作，以及朋友圈中的具体课程产品营销策划与计划内文案；泛朋友圈人设／日常运营未覆盖，业绩管理仍在规划。服务线 `active` 不等于线内任意场景可用。新增模块须先登记、验证并加入发布清单，学员更新后才能接入。每位教练使用自己的已激活人物档案，不把某位教练的城市、经历、产品或文风写成全体默认值。

## 通用选择顺序

1. 先确认教练身份与本地线下会员目标。教同行获客或全国线上招生不路由；同时出现两位教练时先确认对象。若要求“展示技能／安装检查”，先运行 `scripts/show_menu.py`，不要求人物档案。若请求仅属于状态为 `planned` 的服务线，说明尚未交付，不以内容模块代替。
2. 从本人档案读取真实服务区域、客群和业务能力，再依据登记项的 `offer_fit` 匹配。新课程可以由用户自己构造，另设产品资料卡记录草案／已确认／失效状态，不因同一本地业务中的新课程未写进 DNA 就要求整份重建。内部策划可用明确标记的草案；对外成稿需要已确认真实可交付的产品事实。若与本人身份、服务区域、业务能力或公开承诺实质矛盾才回人物模块核对，不能把叶童的女子减脂或旧课程权益当作全体默认值。
3. 候选项要求 `active` 档案时，用其声明的 `profile_check` 核验本人档案。`optional` 模块可处理没有个人事实的通用任务，但要使用本人城市、经历、产品或表达时同样先核验 active。无档案、未激活或结构无效时，不得个性化；对个性化请求显示固定提示并转到产出 `active_profile` 的模块，只缺明确路径时只问路径。
4. 结合登记项的 `purpose`、`use_when`、`avoid_when` 和 `required_any_of`，优先选择能完成用户当前结果且前置条件已满足的模块。多个模块同样适配时才参考 `priority`，不得仅凭关键词或排序数字决定。
5. 需要连续阶段时按前置关系执行；候选题尚未由用户选定，或按其明确授权代选前，不能把它当最终题写稿。没有已登记模块可完成的目标，应说明目前尚未覆盖。

## 新模块接入契约

维护者可在自己的环境制作新 Skill；制作工具本身不属于运行依赖，也不进入发布包。新模块应先按其实际能力填写 `capability-registry.json`：唯一 id 与同名 `SKILL.md` 入口、所属服务线、菜单名称与触发语、逐项批准的 `package_files`、用途、适用和排除情境、档案要求、必要输入、产出、与教练本地产品的适配描述、自己的预检脚本（若需 active 或 optional 档案）、优先级及启用状态。将规划服务线启用前，先交付并验证相应模块，再把状态改为 `active`；不能只修改菜单文案就宣称上线。运行主入口的 `scripts/validate_registry.py` 和 `scripts/show_menu.py` 后，再测试直接／间接请求、缺档案或关键输入、相邻但不应命中的请求、与既有模块的竞争、同主题延展和跨教练隔离。

登记校验只证明结构，不证明路由行为或内容质量。安装环境更新模块后还应重新加载可发现的 Skill 列表；主入口不能假装一个尚未安装或未交付的模块可用。

初次城市信息必须带来源。当前用户明确说过自己的服务城市时沿用；未提供时，六组一次性建档问题的第一组先问城市，再请用户按自己的城市补充区县／商圈，不从示例、他人档案、宿主地点或被否定的假设补全，不把六组默认流程拆成只问城市的一轮。居住地与带课地不一致、多个城市职责不清时，先确认实际服务会员的城市。包内更新先于档案门槛和完整登记校验；内容对象的“更新”仍归相应内容模块，不误执行软件更新。

## 消歧规则

1. 先看平台、当前产品任务与素材成熟度，再看动词。“帮我写减脂”且无课程营销上文仍是宽泛小红书方向；“写一篇回答本地会员担心买课后服务会变的笔记”已经是一个具体问题。前者先选题，后者可直接写稿。要推某门课程或承接既有课程营销计划时，“今天发什么”“接着写”“改成三天”均留在 `yetong-promo`，带着同一产品卡接续。明确要小红书笔记则回小红书路线。无产品上文、只说“朋友圈怎么发”而无法确定课程推广还是日常运营时，只问这个会改变路由的区别。
2. 同时要求“给题再写稿”时按选题 → 文案顺序执行。用户须选题；只有用户明确说“你从候选里选最合适的一题直接写”，才可由系统代选，并说明选择依据。
3. 有现成草稿且说“帮我改顺／重写”时走文案；说“帮我看看整篇哪里不对，先别改”时走内容体检；脱离封面流程只要拟标题、或明确要改笔记发布标题时走标题；说“给这篇设计封面构图／生图提示词／文字排版”时走封面。已经进入原版封面流程后，封面文字的三候选选择、其他阶段的编号回复和素材上传均在封面模块接续，不越权改笔记发布标题，也不重新当作选题。已给定封面文字原样保留。若上轮封面提示词后用户回复“直接生成”或“继续优化提示词”，仍走同一封面任务。若只要求实时平台审核规则或法律审查，则不冒充这些下游 Skill。封面请求不自动变成图片生成请求；明确要求成图也须由封面模块核对素材、权限和工具后执行。
4. 当前会话新说法和档案中本人身份、城市、业务能力或公开承诺实质冲突，或用户指定的教练与档案身份不一致：不静默选择。交回人物访谈核对，或只问本次用哪份档案。新产品资料卡中的草案、价格／权益调整不自动视为人物 DNA 冲突；先由课程模块核对具体课程事实。不得把 A 城市、A 的会员故事写给 B 教练。
5. 内容类型的人设型、营销型、利他型、流量互动型由选题 Skill 标注；文案 Skill 可依据已选题和真实资料选主类与子类。主入口不自行重定义分类。
6. “再出 5 个选题”等承接型短请求，继承最近已完成的具体题或稿件的核心主张，并在任务卡里注明“同主题延展”；不要丢弃上下文当成全新选题池。用户明确说“换个方向”时才清空这一主题约束。若上下文没有可靠的具体主题，则按档案做常规选题。
7. 同时要求文案与封面时，先满足成稿阶段的选题确认，再把本篇实际内容交给封面；同时明确要求优化笔记发布标题与封面视觉时，标题模块先核对文案承诺，封面模块保留已给定封面文字，不把构图设计当成发布标题风险修复。仅未提供封面文字时，原版封面流程按内容给三个候选供编号选择；这不等于已优化笔记发布标题。

## 下游交接最小包

只交接本次所需，不复制档案全文：

```text
固定目标：该教练服务范围内的本地线下会员
人物档案：用户指定或本会话已交接的路径；profile_id／display_name；核验结果
当前能力：从登记表选中的模块 id 与所需前置输入
本地内容依据：真实城市及到店区域；客群片段；具体顾虑和来源；本人的产品、经历／服务动作／证据
六组资料取用：本篇相关的场馆优势、主要服务人群与表层／深层痛点、真实客户问答、身份／资质／标准／课外服务、高光／匿名案例、选择理由；标记来源、频率、缺失与权限，不全量复制
已选题：具体问题与角度、工作标题、主内容类型、筛选理由；若无则标记未选
事实边界：已确认可公开、待确认、仅内部使用、禁止公开；条件性做法与已发生个案分开
本轮要求：数量、形式、目标人群、原标题或已有稿件（若有）
课程营销（若涉及）：独立产品资料卡及草案／已确认／失效状态；真实目标、适合／不适合人群、课程内容／价格／权益／标准；授权素材；计划版本、当前日序与已执行内容；本轮要计划还是写／改文案、可执行频率；内部提纲不可直接发布，对外事实须已确认真实可交付
封面素材（若涉及）：图1人物参考；图2起真实器械／产品／界面／场景等辅助素材与逐项授权、是否明确要生成图片；缺失时标记缺失，不想象有图
封面接续（若涉及）：当前原版单题阶段、已选构图／动作／背景／封面文字及编号；上轮完整提示词与排版清单、当前窗口工具能力、用户回复“直接生成”或“继续优化提示词”；无可靠上文时标为未交接
承接关系：同主题延展及其上一主题／同一产品计划续写及当前日序／明确换方向／无可靠上一主题
```

目标 Skill 仍须自行读取同一个 `person-dna.md`，复核其规则。主入口的预检不替代下游的事实与权限检查。旧版已激活 `schema_version: 2` 档案继续按已有事实工作；没有证书、三件高光或新六组细分字段不意味着失去激活状态，只在本篇确实需要缺失信息时最小补问。
