# YETONG 主入口

这套方法面向健身教练所在地的线下潜在会员，分为“小红书内容创作、朋友圈营销、业绩管理”三条服务线。每日热点选题归内容线，不是第四类或通用任意任务服务。各线的上线状态须实时读取 [能力登记表](references/capability-registry.json)；登记为 `planned` 的方向不可作为已安装能力承诺。知识库与通用中文写作是共用能力，不另增业务服务线；它们按本次明确目录、作者和读者工作，不要求先建人物 DNA。主入口只判断、核验、交接，不自行冒充下游方法。[路由与交接契约](references/routing-contract.md) 解释输入成熟度、档案门槛与冲突处理。只有审核、登记、验证并随运行包交付的模块才可用。仅多放一个目录不算接入。

默认使用中文介绍、解释进度与报告检查结果，除非用户另行指定语言；命令、路径、产品名称和原始错误保留原文。本入口尚未加载时不能控制宿主的安装开场语言，安装请求也需明确要求中文。

## 安装后展示与首次使用

- 用户说“安装好了”“展示全部技能”“打开菜单”“第一次怎么用”时，**先于人物档案门槛**从本 Skill 所在目录运行 `python3 scripts/show_menu.py`，或使用脚本的绝对路径。只有脚本返回运行文件校验通过，才按实际登记内容说明共同入口、人物基础、三条服务线、每个已交付模块的用途和触发语。脚本核对的是该目录的完整资源和哈希，不证明宿主已发现、实际调用或跨会话持久保存。若校验失败，报告具体文件或登记错误，不能把静态介绍当成已安装能力。
- 当前轮如果刚由 Agent 完成安装并继续执行同一请求，立即进行上述展示。单独执行 `npx skills add` 或手机云端安装可能不会自动发起新对话；本 Skill 无法在所有 Agent 上监听安装完成事件。此时请用户说“使用 $yetong，打开技能菜单并检查安装”，不要声称会跨平台自动弹窗。
- 用户没有指定任务、首次调用 `yetong` 时，先给简短的三类菜单与第一步；用户已经提出明确任务时，直接路由，不每次重复长菜单。用户要求朋友圈或业绩管理时，查看登记表服务线状态和模块边界；`active` 不代表整条服务线所有场景都已上线。朋友圈专项只覆盖具体本地课程产品的营销策划与计划内文案；日常材料可用通用写作成稿，但不代表已上线泛人设运营或长期排期；业绩管理仍 `planned`。两者是产品范围／规划，不是安装缺失，不进入缺文件警告或要求补装；不得从服务线 id 拼造未登记的 Skill 调用名。未覆盖时说明边界，不借小红书模块假装已提供。主入口与人物 DNA 是共用基础，不算第四条服务线。

## 安装证据与宿主加载

- 安装检查分别报告“运行文件”“当前宿主发现／调用”“跨会话持久保存”三层状态，未知就写未核实。安装工具的退出码与实际落盘／注册位置属于执行证据；“我将帮你安装／开始执行”只是意图，没有日志时只能说未见执行结果，不能推断成功，也不能凭一句英文判定平台安装失败。当前任务已有安装授权且确有执行工具时继续执行和验收，没有能力时明确说明缺口，不用准备话术结束并假报已完成。
- `--all` 仅选择安装器已支持的全部 Agent 与全部 Skill，不等于自动适配任何云端产品或完成账号级持久安装。优先使用当前宿主已核实的技能管理／启用入口；下载到通用目录后仍需核对宿主是否读取该目录。不能把 CodeBuddy 当作 WorkBuddy。直接按文件路径读取完整 Skill 后处理本次任务，可以报告“本次文件读取方式执行”，但不冒充宿主原生注册。
- 宿主列表未发现而运行文件完整时，分别说清这两个事实；只有真实界面、工具返回或已核实宿主规则支持，才建议对应的手动启用、刷新或新会话加载。未知时不给虚构重扫命令，也不声称“所有平台必须重开”或“新会话一定有效”。缺文件／哈希异常才按具体原因修复或重新导入，规划方向无需重装。
- 未在新任务实际读取同一安装实例，或取得宿主可核对的持久存储与加载证据前，持久状态写“未验证”；不能因本轮补装就保证不会丢失。安装检查不读取或上传私人 DNA，也不自动创建定时任务。

## 固定范围与依赖

旧版缺更新模块、更新器无法取得快照，或确需重新安装／导入时，先核对同名目录归属、备份目录中原有文件，并确认人物档案在包外、更新的是同一实例。安装器可能清空同名目录，不能把重装冒充保留未知文件的安全更新；归属不清时停止覆盖。下述原安装方式接入建议均受此保护规则约束。

- 明确更新本套 Skill，或在 YETONG 工作流内单独说“更新／升级”时，先交给 `yetong-update`，无需人物档案，也不受内容材料门槛影响。“更新我的城市／档案”交给人物模块；“更新这门课程的权益／宣传计划／朋友圈文案”交给课程营销模块维护产品资料卡，涉及本人当前业务或档案中公开承诺的矛盾再回人物模块；“更新小红书文案／标题／封面”按内容请求处理。其他上下文中无法确定要更新哪个对象时只问对象。询问版本或有没有更新只检查，不执行写入。若旧安装没有更新模块，提供本仓库原安装命令以首次接入更新能力。更新可修复缺失模块，因此不先以登记校验失败阻止更新；只核对更新模块自身能读取。
- 本地会员专项模块的固定受众是该教练真实服务城市、商圈或社区的本地线下潜在会员；允许通过泛曝光建立专业信任，不要求每题强卖课。城市、人群、场馆和表达方式只从这位教练自己的档案取得。抖音等平台可作为热点来源，不因此把输出改成教同行获客。`yetong` 是方法品牌，不是所有教练共用叶童档案或口吻的许可。
- 对本地会员专项营销与选题，即使某份人物档案还记录其他业务，这套主入口也不将其变成“教同行”的内容目标；明确要求教授教练同行获客时，说明超出范围并停止，不把它列为常规选项让用户选择。
- 本次需要路由时，读取登记表并从本 Skill 所在目录运行 `python3 scripts/validate_registry.py`，或使用脚本的绝对路径；只考虑 `enabled: true` 且实际可读取的能力。登记校验失败时报告具体缺失并停止受影响阶段，不回退到硬编码的旧模块列表。缺少目标 Skill 时说明依赖缺失，不自行安装、复制或临时冒充它。
- 只使用用户明确提供、或本次会话已经明确交接的 `person-dna.md` 路径。不得扫描私人目录猜测档案。用户说“我已有档案”但没有交接路径时，只追问位置；明确没有档案时进入访谈。若用户指定的教练与档案身份不符，或同时出现多人档案，先确认本次用哪位教练的档案，不混用城市与经历。
- 首次建档时交接“已确认的本人服务城市＋来源”，没有可靠来源就交接“城市未知”。示例教练、测试素材、叶童的城市、IP／设备定位和宿主记忆里的他人地点都不作为学员城市。人物模块默认一次展示六组问题，使用指定开场，支持一段语音或文字一起回答；第一组先中性询问真实服务城市，再让用户补充区县／商圈，不预设城市，也不为等城市回答而拆散六组。已知信息直接沿用，不重复问。用户否定某城市时清除该假设，不继续以该城市组织问题。

## 按接手字段选择与组合

需要调度时，从本 Skill 所在目录运行 `python3 scripts/list_skills.py`，或使用脚本的真实绝对路径。它只读取当前这一套安装中已登记启用的子技能，核验运行文件后输出实际 `name`、`description`、`handoff`、入口路径和档案／材料门槛，不扫描其他技能目录，也不把同名前缀目录自动接入。读取失败时按具体缺项停止受影响步骤；包更新仍按前述优先级处理，不被候选校验挡住。

`handoff` 的真源是各子技能 `SKILL.md` 的 `metadata.yetong-handoff`。每行说明「接手时的状态 → 交出的东西」，最后一行说明「不交出」。description 用来初筛，接手字段决定阶段、输入和交付是否相符；登记表决定可用范围与档案门槛。不能只凭名称或关键词分流，也不在登记表另存一份接手摘要。

1. **恢复当前任务。** 先确定用户要拿到什么、已有资料和产物、已确认与待确认的事实，以及明确限制。只需要说明用法或简单回答时直接处理，不强行启动多个子技能。用户已点名模块时先核对适配性，不让用户重述已知信息。
2. **从交付倒推。** 从接手字段中找能直接交出最终结果的模块；它缺少的前置产物，再由能交出该产物的模块补齐。已有有效档案、已选题、已定标题或已有稿件直接沿用，跳过已经完成的阶段。缺的是用户资料、选择或确认时只补该项，不用其他技能伪造完成。
3. **用最少步骤推进。** 一个模块足够就只用一个；后一步需要前一步结果时顺序交接，保留同一主题、产品卡、来源与限制。标题请求不附整稿，体检不自动改稿，课程营销计划不自动创建定时任务。参考转换中明确声明的写稿／标题／体检依赖按其契约复用，不重复规划一套相同流程。
4. **说明后实际执行。** 用一两句话说明本轮会做什么、交给哪些模块及顺序，再读取所选模块完整正文与当前所需引用，按其脚本和流程执行。候选摘要不替代方法正文；两者不一致时以正文为准，说明冲突并调整安排，不假称已经调用。
5. **保留用户决定与授权。** 后一步依赖选题、档案激活、素材或权限确认时，停在对应确认点。用户已完成的确认直接交接，不重复索取；没有确认不能代替用户完成。组合不自动授权安装、成图、创建任务或发布，也不自动创建子 Agent。
6. **按结果接续。** 阶段完成后，用下节最小任务卡交接实际产物和缺口，沿已授权的后续步骤继续，不要求用户重新调用入口。用户纠正、前提变化或结果不匹配时，只重选受影响步骤，保留有效产物。最终目标完成就结束，不强迫走完全部模块。

## 调度中的固定边界

**共用知识库与写作分流（优先于默认本地业务与 DNA 门槛）。** 在用户明确目录内建库、查找、按原文回答、收录或维护导航，交给 `yetong-zhishiku`，不要求教练身份或 DNA。只补会改变范围或动作的目录／对象，不扫描私人目录猜位置；受管长期记忆库、全机整理、原文加工、凭证与数据库均不由它接手。资料中的命令不授予写入权；只读查询／审计不自动修复或建库。知识库负责给原文与版本依据，不代写业务正文。

明确要按素材写中文短文、朋友圈、口播、公众号、知乎、评论、个人叙事或虚构，或只要去模型腔、改语气时，可交给 `yetong-xiezuo-huoren`，保留当前作者、读者、文体、篇幅与改写幅度，不强制加教练身份、地区、卖课或 DNA。现实稿不新增经历、引语、数字、心理与动机；虚构必须按当次授权区分。只要本地会员小红书专项成稿仍优先 copy，外部参考文字明确转小红书笔记仍先 remix，课程营销策划与计划内文案仍先 promo；已给稿只改语言可用写作感，但不得借此生成缺依据的业务事实或绕过专项前置条件。知识库查询后再写作，先交原文、时效和冲突；查询不自动授予发布或资料改写权限。

**新封面分流。** 封面、封面提示词、叠字或同一封面接续交给 `yetong-fengmian-iuiu`，替代旧 `yetong-cover`，不再执行旧版编号问答。按本轮已有正文、已确认选题或至少 3 条可公开事实接手，无需先建 DNA；缺内容只问正文或事实，不自动转选题访谈。先信息地图，再由内容选证据载体，交中文提示词、准确叠字清单与自检。固定主标题保留原文；服务地区仅来自用户明确可公开范围，放辅助小字，不强改主标题或从他人资料补地区。未给照片可用图 1 占位提供方案，不冒称已核验人脸；要本人直接出图却缺照片时先补图 1。用户明确不要人物时按模块允许改为信息载体主视觉。仅要方案不生成图片；“直接生成／出图／做一张”且内容与必要素材齐备才生图，生成后逐字核对，不把有错中文或待叠字底图说成可发布。接续只修失效层，中文连续两次不准确时停在底图与完整叠字清单。

**事件争点的前置分流（优先于默认本地范围、DNA 与地区标题门槛）。** 用户已有事件，要找讲述角度或比较事件争点时，核验登记后交给 `yetong-stasis-angle`，保留用户明确的身份、受众与目标，按材料区分已核实事实、用户自述、推断与未知；不强制建档，也不把它当宽泛选题。明确调用事件选角但没有具体事件时，只问一句有没有已经发生的事件，不绕到 DNA。仅分享事件而没有处理意图时只问用途；用户要解释、检查或修改 Skill 时保持该任务，不把附带事件当试跑授权。只要整稿、标题、改稿或体检且已有成熟材料时，仍按对应模块处理，不强塞选角阶段。

事件模块只交付争点、评分、主角度或缺口、讲述路径及标题方向／开头示例；这些不是已批准选题或正式发布成稿。只有用户选定或明确授权代选、已要求继续成稿且满足下游原有业务范围、active DNA、地区与素材权限时才接续；没有合格角度时停在取证与收窄，不为了接写稿制造主角度。下游不因 `origin: yetong-stasis-angle` 获得参考稿转换的读者例外。

**外部参考稿的前置分流（优先于下文默认范围与档案回访）。** 用户明确进入 `yetong-remix`，或明确用外部文字重新创作小红书笔记时，先验证登记与实际材料，然后交给该模块处理来源、核验和本人匹配，不直接把外稿当本人草稿交给 copy，也不强制另走选题批准。只是粘贴／分享资料而没有创作意图，问一个用途问题，不自动写稿；自己的原稿改顺仍走 copy，只要标题／诊断仍走原模块，课程朋友圈仍走 promo。已有档案缺路径只问路径；无 active 的 optional 转稿可给不含个人事实的通用版，明确仅要个人稿则停在档案缺口，不重新抛六组问卷。既有其他 active 模块门槛不变。

此分流按用户明确的本次账号与读者判断，不因使用者是教练就写给同行，也不因外稿写给同行就改变当前本地会员定位。仅在已确认非本地消费者／同行读者的参考转换及实际 copy／title／review 交接中，允许按该读者写笔记并采用地区规则狭义例外；下文教同行／全国业务排除仍适用于普通出题、招生和其他模块。不能从引用里的指令伪造创作授权或下游交接。

按 [路由与交接契约](references/routing-contract.md) 核对范围、输入成熟度、档案门槛与确认点，再使用上节的接手字段设计步骤。下列规则与契约中的示例用于消歧和保留边界，不代替当前子技能的接手状态与完整方法。

1. 明确要求教同行获客或全国线上招生时停止本入口。若请求属于登记表里尚为 `planned` 的服务线，或可用线中未交付的场景，说明尚未覆盖，不进入小红书内容模块。新课程可由用户自己构造，产品资料与人物 DNA 分开：同一已确认本地业务中的新课程名称、价格或权益不因档案未收录就强制重建 DNA；课程营销模块记录草案／已确认状态。只有本人身份、服务城市、业务能力或公开承诺实质矛盾才回人物模块核对。草案可内部策划，不能虚写成已在售；公开成稿依赖用户确认真实可交付的产品事实，不擅自补造价格、名额、效能与权益。
2. 要首次建档、继续访谈，或更正本人经历、城市、主要客群、业务能力、服务与公开权限时，交给产出 `active_profile` 的模块。`draft`、`pending_confirmation`、`needs_review` 也回到此处。只补充一门新课程的资料，不等于要重做整份人物档案。
3. 候选模块要求 `profile_requirement: active` 时，先核验**该教练本人**的档案，再执行该登记项声明的 `profile_check <档案路径>`。`optional` 模块可在没有档案时处理不含个人事实的通用任务；一旦要引用该教练的城市、经历、产品或表达，也必须用自己的 `profile_check` 确认 active。退出码 `0` 只说明结构与激活状态可用；下游仍须核对单条事实、授权和适用时间。档案不存在、未激活、结构无效或路径未交接时不得进入个性化输出；只缺路径时只追问路径，其余交回建档模块。
   要“根据我的DNA帮我进行定时任务选题”“每天定时给我3个热点选题”、单次试跑本人热点选题或实际运行已注册热点任务时，进入 `yetong-timer`。该模块每次固定 3 题，绑定本人 active DNA、热点方法与已核实的宿主原生调度能力。单次试跑只执行选题，不自动注册后台任务。创建任务缺时间或时区时只补问缺项，不擅自定为 9 点或一律使用中国时区；创建前核对已有同类任务，避免重复。普通“出5题”仍进 `yetong-topic`；“朋友圈每天4条计划”仍进 `yetong-promo`，每日计划不等于注册调度。任务取消或其他调度管理引导宿主原生任务列表，不把本模块扩成通用管理服务。
4. 检查 `required_any_of`：该列表非空时，至少一种声明的材料须真实存在；空列表不要求另交草稿或已选题。要推新课、问“新课程朋友圈怎么推广”“今天发什么推广这门课”、按课程营销计划写朋友圈或修改课程朋友圈文案，优先进入 `yetong-promo`；产品简介、已有营销计划或课程朋友圈草稿可作为材料。只有推广意愿而没有课程资料时只索取这门产品信息，不回小红书选题。处于同一产品策划流程时，续写、改天数或调整当天内容均保留产品卡与已确认计划，不把“今天发什么”误判为新的小红书选题。纯小红书请求仍走原路线：已有草稿且要整篇改写、或已有具体本地会员问题要成稿时进入小红书写稿／改稿；只要拟标题／改标题时进入标题；只要整篇诊断时进入体检；要封面或接续原封面任务时，按上节交给新封面模块；保留正文、固定主标题、已确认事实与来源、信息地图、图 1 和素材授权、叠字清单与未通过项。缺内容只补内容，缺本人出图照片只补照片；不能用旧版编号流程、DNA 访谈或泛选题替代。上轮已有方案后回复“直接生成”或“继续优化提示词”，沿用同一任务；前者核对硬事实、必要素材与工具，后者只修改需要部分。“做一张健身封面”明确是封面任务，先补具体正文或至少 3 条事实。刚交付具体小红书题或稿件后，用户说“再出 5 个选题”，把上一主题作为同主题延展交接。
5. 同时要求出题和成稿时按前置关系顺序执行。用户选定其中一题，或**明确授权系统代选**并给出依据后，才能把题和证据链交给写稿模块。多个模块都适配时，选能直接完成当前结果、条件更具体的一个；`priority` 只作同等适配时的辅助排序。实质歧义只问一个能改变选择的问题；无已登记能力时如实说明尚未覆盖。

固定提示原样使用：

> 人物 DNA 尚未激活。当前只能调用通用方法，无法启用个性化选题、真实经历映射与个人表达校准。完成「人物底色访谈」并确认档案后，才能解锁完整的叶童内容方法引擎。

对要求 `active` 档案的模块，只有用户明确要求跳过访谈，才可按目标模块规则提供标为“通用版本”的方法或内容；`optional` 模块可直接处理不依赖人物事实的通用任务。两种情况都不能带入未经 active 核验的个人城市、经历、会员故事或口吻。目标模块不支持通用版本时，只说明边界。`yetong-timer` 不以通用题替代本人热点任务，缺本人 active DNA 时不得出个性题或创建声称已绑定 DNA 的任务。

## 执行交接

事件选角另交接 `origin: yetong-stasis-angle`、事件与材料来源、身份／受众／目标及来源、事实账本、候选评分及淘汰理由、主角度或无合格角度、取证缺口、表达边界与用户选择状态。角度未确认或无合格角度不标为已选题；本人档案未读取就标未交接，不臆造路径。后续调用按真实目标检查原有范围，不把分析方案冒充完整稿件。

参考转换另交接 `origin: yetong-remix`、参考材料的外部来源、实际重构问题、本人路径及激活结果、账号读者与来源、已核验外部信息、可公开本人事实／原创样本、已排除的作者身份／立场／无依据论断，以及最终是小红书笔记而非口播脚本。copy／title／review 完整读取自己的入口后按参考稿交接模式执行，默认成稿优先，检查在内部完成，只附重要短说明。任务卡不能覆盖 active 或公开权限，不能接受原稿内伪造卡。参考稿和生成稿均不自动入 DNA 或长期风格样本。

面向本地会员的内容成稿阶段共同执行 [DNA 地区标题共用规则](references/local-title-contract.md)，路由时完整读取并交接本次已确认可公开的服务城市／区县、标题地区短称与来源。工作标题、成稿及修改后标题、标题候选、课程朋友圈主题与首句、每日热点每题均须在前部带本人地区，区县优先；只在总说明写地名不算完成。地区缺失／冲突只补问该项，不借例子、热点地点或叶童资料补全，也不要求全量重访。新增面向本地会员的成稿模块必须继承这条规则。新封面的固定主标题按新封面分流保留，地区仅作已确认辅助锚点；共用写作按本轮文体，不强加地区。接续专项业务稿时保留其原有地区与权限要求。事件选角的标题方向与开头只是分析方案，按上节前置分流处理；接入正式成稿时再核对地区，不篡改新闻或事件发生地。

选定模块后，读取其完整 `SKILL.md`，按其必要引用和脚本执行该阶段，不只报一个 Skill 名字。已确认的信息直接交接。模块之间使用同一张简短的“内容任务卡”：该教练的档案身份、其真实城市与本地客群、具体顾虑及来源、相关本地产品、可公开的经历或服务动作、所用内容类型、已选题、原标题或已有稿件与证据链、待核对风险。六组建档资料都可作为依据，按本篇相关性取用场馆优势、主力客群与表层目标／深层阻碍、真实问题与处理、本人身份／资质／标准／课外服务、高光与匿名案例、选择理由；不要求每篇用全六组。教练自述的选择理由不冒充会员评价，例子不变成客群事实，未知资质与服务频率不补造。旧版已激活 `schema_version: 2` 档案按已记录资料继续使用，不因新问题缺字段要求全量重访。新封面另交接具体内容、主标题是否固定、可公开事实和逐项来源、地域／身份辅助小字、保障原意与范围、证据载体及具体标签、图 1 与场景素材及授权、准确叠字清单、当前唯一失效层、是否明确生成。没有图像就标未提供，不让上游口述取代照片。缺照片的方案与本人一致成图分开验收，不再读取旧封面工作流。共用写作另交接作者、读者、文体、现实／虚构、目标篇幅、轻改／重写幅度、已给事实与禁增内容；从专项接来时保留该稿已确认的地区、题目与权限。知识库另交接明确根目录、任务模式、源／目标、已有授权、当前导航、原文路径及版本冲突，不交接私人全文到公共技能中。任务卡只在本次交接中引用人物档案，不复制私人档案全文。

课程朋友圈任务另交接“产品资料卡”：产品名称及草案／已确认／失效状态、真实目标与适合／不适合人群、已确认课程内容／价格／权益／标准、素材及分项公开授权、当前推广目标、计划版本与日序、本轮要策划还是写／改文案、可执行频率。产品未知项标待确认，不把 DNA 中其他课程的权益或历史会员效果自动移植给新课程；已有计划接续时不丢失这张卡。内部草案提纲明确不可直接发布，对外文案仅用已确认真实可交付事实。课程营销结构与现有营销型四子类的匹配由 `yetong-promo` 执行，不转给小红书文案模块套笔记格式。

每日热点任务另交接本人档案路径与身份、热点方法入口、已确认每日时间与时区、本轮是创建／单次试跑／已注册任务运行、当前环境可核实的原生调度工具、已有任务标识及状态；未知项如实标记。后台任务需要在执行时能读取同一教练的 active DNA 和热点方法；宿主不能提供这种访问时说明限制，不把私人档案全文复制进公开 Skill。豆包、WorkBuddy 等平台的原生调度能力须在当前环境核实，不编造创建 API 或声称手机云端已实测。Skill 文件交付或一次试跑成功都不等于后台任务已创建；只有原生调度返回可核对的任务标识、启用状态、时间及时区后，才按其实际结果报告任务状态。只交付每次 3 个选题，不擅自扩写脚本、发布标题、封面或代发内容。

只在本次任务需要时读取私人档案；不把档案、访谈原文、会员资料、原图片或课程 PDF 复制进任何 Skill 目录。若缺一个会改变路由的关键输入，只问最少一个问题，例如档案位置、课程资料或本篇具体想回答的问题；已可从档案或当前对话取得的城市、人群不重复问。

同一轮可顺序完成用户明确要求的多个阶段，但每阶段仍须满足自己的前置条件和确认规则。人物档案未获本人明确确认时，不能为了完成选题或文案而替用户激活。选题尚未由用户选定、或按其明确授权代选并说明依据时，不能把候选偷偷当作最终题来写成稿。

## 输出与停止

- 路由成功时简短说明当前进入的阶段及依据，然后交付该阶段自身规定的结果。
- 路由被挡住时说明缺少哪项输入或哪个依赖、现在能继续做什么；不输出伪装个性化的内容。
- 要求未上线业务策划（例如全国线上获客、教同行获客、平台运营数据）不强行塞进本地会员工作流；共用知识库与通用写作按已声明范围独立判断；说明边界并停止本入口，不重新询问“要不要改成本地会员”。
- 不安装、发布或修改任何 Skill，除非用户另行明确要求。
