# YETONG 主入口

这套方法面向健身教练所在地的线下潜在会员，分为“小红书内容创作、朋友圈营销、业绩管理”三条服务线。各线的上线状态须实时读取 [能力登记表](references/capability-registry.json)；登记为 `planned` 的方向不可作为已安装能力承诺。主入口只判断、核验、交接，不自行冒充下游方法。[路由与交接契约](references/routing-contract.md) 解释输入成熟度、档案门槛与冲突处理。只有审核、登记、验证并随运行包交付的模块才可用。仅多放一个目录不算接入。

## 安装后展示与首次使用

- 用户说“安装好了”“展示全部技能”“打开菜单”“第一次怎么用”时，**先于人物档案门槛**从本 Skill 所在目录运行 `python3 scripts/show_menu.py`，或使用脚本的绝对路径。只有脚本返回安装校验通过，才按其实际登记内容说明共同入口、人物基础、三条服务线、每个已安装模块的用途和触发语。若校验失败，报告具体缺失，不能把静态介绍当成已安装能力。
- 当前轮如果刚由 Agent 完成安装并继续执行同一请求，立即进行上述展示。单独执行 `npx skills add` 或手机云端安装可能不会自动发起新对话；本 Skill 无法在所有 Agent 上监听安装完成事件。此时请用户说“使用 $yetong，打开技能菜单并检查安装”，不要声称会跨平台自动弹窗。
- 用户没有指定任务、首次调用 `yetong` 时，先给简短的三类菜单与第一步；用户已经提出明确内容任务时，直接路由，不每次重复长菜单。用户单独要求朋友圈或业绩管理时，查看登记表服务线状态；若仍是 `planned`，说明规划方向和目前没有专项能力，停止专项路由，不借小红书模块假装已提供。主入口与人物 DNA 是共用基础，不算第四条服务线。

## 固定范围与依赖

- 固定目标是该教练在其真实服务城市、商圈或社区获得本地线下会员；城市、人群、场馆和表达方式只从这位教练自己的档案取得。`yetong` 是方法品牌，不是所有教练共用叶童档案或口吻的许可。
- 即使某份人物档案还记录其他业务，这套主入口也不将其变成“教同行”的内容目标；明确要求教授教练同行获客时，说明超出范围并停止，不把它列为常规选项让用户选择。
- 本次需要路由时，读取登记表并从本 Skill 所在目录运行 `python3 scripts/validate_registry.py`，或使用脚本的绝对路径；只考虑 `enabled: true` 且实际可读取的能力。登记校验失败时报告具体缺失并停止受影响阶段，不回退到硬编码的旧模块列表。缺少目标 Skill 时说明依赖缺失，不自行安装、复制或临时冒充它。
- 只使用用户明确提供、或本次会话已经明确交接的 `person-dna.md` 路径。不得扫描私人目录猜测档案。用户说“我已有档案”但没有交接路径时，只追问位置；明确没有档案时进入访谈。若用户指定的教练与档案身份不符，或同时出现多人档案，先确认本次用哪位教练的档案，不混用城市与经历。

## 路由顺序

按 [路由与交接契约](references/routing-contract.md) 先看范围和用户想要的结果，再比较登记表里各模块的用途、适用／排除情境、输入和产品适配；示例不是简单关键词触发器。

1. 明确要求教同行获客或全国线上招生时停止本入口。若请求属于登记表里尚为 `planned` 的服务线，说明尚未交付专项 Skill，不进入小红书内容模块。用户提出另一项本地健身产品／服务时，先看它是否属于这位教练档案中已确认、当前真实可提供的业务；缺失或冲突则交给登记表里产出 `active_profile` 的模块核对，不替教练发明产品。
2. 要首次建档、继续访谈，或更正经历、城市、客群、产品、服务与公开权限时，交给产出 `active_profile` 的模块。`draft`、`pending_confirmation`、`needs_review` 也回到此处。
3. 候选模块要求 `profile_requirement: active` 时，先核验**该教练本人**的档案，再执行该登记项声明的 `profile_check <档案路径>`。`optional` 模块可在没有档案时处理不含个人事实的通用任务；一旦要引用该教练的城市、经历、产品或表达，也必须用自己的 `profile_check` 确认 active。退出码 `0` 只说明结构与激活状态可用；下游仍须核对单条事实、授权和适用时间。档案不存在、未激活、结构无效或路径未交接时不得进入个性化输出；只缺路径时只追问路径，其余交回建档模块。
4. 检查 `required_any_of`：至少一种声明的材料须真实存在。已有草稿且要整篇改写、或已有具体本地会员问题要成稿时，进入写稿／改稿能力；已有具体选题、原标题或草稿而只要拟标题／改标题时，进入标题能力；已有具体选题或草稿而只要整篇诊断时，进入内容体检能力；已有**具体且选定**的本地会员选题或草稿而要封面构图、生图提示词、实拍计划或文字排版时，进入封面能力。若上一轮封面模块已交付可执行提示词，本轮只回复“直接生成”或“继续优化提示词”，沿用同一封面任务并回到封面模块；不把这两个短回复当作新选题或写稿请求。“直接生成”仍须由封面模块核对工具、素材与授权。单独一个原标题若无法明确本篇问题或正文承诺，不等于封面的选题材料；“想写减脂”“帮我写点内容”“做一张健身封面”仍是宽泛方向，先交给能产出选题候选的模块。刚交付具体题或稿件后，用户说“再出 5 个选题”，把上一主题作为同主题延展交接。
5. 同时要求出题和成稿时按前置关系顺序执行。用户选定其中一题，或**明确授权系统代选**并给出依据后，才能把题和证据链交给写稿模块。多个模块都适配时，选能直接完成当前结果、条件更具体的一个；`priority` 只作同等适配时的辅助排序。实质歧义只问一个能改变选择的问题；无已登记能力时如实说明尚未覆盖。

固定提示原样使用：

> 人物 DNA 尚未激活。当前只能调用通用方法，无法启用个性化选题、真实经历映射与个人表达校准。完成「人物底色访谈」并确认档案后，才能解锁完整的叶童内容方法引擎。

对要求 `active` 档案的模块，只有用户明确要求跳过访谈，才可按目标模块规则提供标为“通用版本”的方法或内容；`optional` 模块可直接处理不依赖人物事实的通用任务。两种情况都不能带入未经 active 核验的个人城市、经历、会员故事或口吻。目标模块不支持通用版本时，只说明边界。

## 执行交接

选定模块后，读取其完整 `SKILL.md`，按其必要引用和脚本执行该阶段，不只报一个 Skill 名字。已确认的信息直接交接。模块之间使用同一张简短的“内容任务卡”：该教练的档案身份、其真实城市与本地客群、具体顾虑及来源、相关本地产品、可公开的经历或服务动作、所用内容类型、已选题、原标题或已有稿件与证据链、待核对风险。封面阶段还须交接可用实拍素材、肖像／场馆／会员素材授权、已给出的提示词与用户后续选择，以及希望得到方案还是成图；未明确请求生成图片时不主动调用生图工具。任务卡只在本次交接中引用人物档案，不复制私人档案全文。

只在本次任务需要时读取私人档案；不把档案、访谈原文、会员资料或课程 PDF 复制进任何 Skill 目录。若缺一个会改变路由的关键输入，只问最少一个问题，例如档案位置或本篇具体想回答的问题；已可从档案或当前对话取得的城市、人群不重复问。

同一轮可顺序完成用户明确要求的多个阶段，但每阶段仍须满足自己的前置条件和确认规则。人物档案未获本人明确确认时，不能为了完成选题或文案而替用户激活。选题尚未由用户选定、或按其明确授权代选并说明依据时，不能把候选偷偷当作最终题来写成稿。

## 输出与停止

- 路由成功时简短说明当前进入的阶段及依据，然后交付该阶段自身规定的结果。
- 路由被挡住时说明缺少哪项输入或哪个依赖、现在能继续做什么；不输出伪装个性化的内容。
- 范围外请求（例如全国线上获客、教同行获客、平台运营数据）不强行塞进本地会员工作流；说明边界并停止本入口，不重新询问“要不要改成本地会员”。
- 不安装、发布或修改任何 Skill，除非用户另行明确要求。
