# 人物、证据与平台表达

## 档案读取顺序

1. 只读用户明确指定的档案，不搜索整台电脑找私人资料。
2. 前置脚本只证明结构和激活状态，不能证明单条事实真实或已获公开许可。
3. 从档案取：当前身份与本地服务范围、对应客群的真实顾虑、可公开的服务动作、本人原话与表达指纹、选题相关故事及独立授权边界。
4. 如果当轮对话与档案相冲突，指出冲突并请本人核对；重大身份、城市或业务改变应先回人物访谈更新档案。

六组新增资料不改变原有激活门槛：旧版 `schema_version: 2` 有效且已激活就可继续写稿。新增字段未提供时不补造、不要求完整重访；当前稿件确实用不到就不问。

## 六组资料的按篇使用

先选本篇对应的本地客群和其实际表达的目标／阻碍，再按主类型取 1～3 项相关依据。访谈里的“环境好、器械好、宝妈、减脂、平台期、怕跑路”等举例只帮助教练回答，不自动写进档案或正文。

| 主类型 | 优先取材 | 转成正文的方式 |
| --- | --- | --- |
| 人设型 | 称呼、角色、入行年限、已核对资质、真实高光与个人选择 | 讲清一个真实节点或做事方式，凭具体行动体现优势 |
| 营销型 | 本地会员顾虑、场馆特点、课程标准、课外服务、获授权的匿名案例 | 回答一个顾虑，用实际交付过程或授权个案说明，不堆权益或许诺人人有效 |
| 利他型 | 主要客群的真实目标和训练阻碍、本人擅长领域、实际指导方法 | 解释一个有限的判断或做法；饮食建议与跟踪按本人提供的方式和频率写 |
| 流量互动型 | 客群真实处境、客户原话、到店或训练取舍 | 围绕具体处境提问，收集反馈；不代替用户断定某人群的共同焦虑 |

“一句话场馆优势”和“客户为什么选择我”保留为教练自述，并用可核对的设施、标准或真实行动支撑；没有客户原话时不写成“会员都说”。证书需要核对具体名称与所能支持的专业范围，不由证书推导疗效。匿名最佳案例只用单独获准公开的事实；不知道姓名并不等于已获照片、体重、聊天和健康资料的公开许可。

会员需要被如何称呼、教练平常怎样解释一个问题，以六组回答的原话和已确认文风为准；三件高光和全部标准是素材池，不是每篇必填项。

| 档案状态 | 写稿用法 |
| --- | --- |
| 已确认且可公开 | 可写进工作稿，仍须符合时间范围和语境 |
| 已确认但需再次确认 | 可帮助选结构，不能直接写成发布事实 |
| 仅内部使用 | 只用于决策，不得在正文或画面泄露 |
| 禁止使用／未授权第三方 | 不直接或间接使用 |
| 待确认／无来源／已失效 | 不当作当前事实；需要时列为补充问题 |

一个会员同意匿名公开体重变化，不等于同意公开照片、聊天、姓名或健康详情。小城市的具体场馆、时间与身材数据组合也可能反向识别。

## 保留素材的语义身份

人物档案提供的是不同种类的材料，不只是“可用／不可用”两档。写稿前辨认：

| 素材是什么 | 可写成什么 | 不能偷换成什么 |
| --- | --- | --- |
| 已确认且获准公开的真实个案 | 有时间、人物关系、行动和结果依据的故事 | 比已授权范围更具体的身份或结果 |
| 客户转述的担忧或问题 | “有人担心／有人问过……”；逐字引号只用于确实提供的原话 | “某场馆已经这样做”“多数客户都遭遇过”之类未证实事件或比例 |
| 教练描述的条件性处理办法 | “如果遇到……我会考虑……”；说明适用条件 | “有一位会员后来……”这种没有发生依据的真实案例 |
| 教练对原因或效果的判断 | 带主体和边界的本人看法 | 已核实的因果、统计结论或普遍效果保证 |
| 教练概括的场馆优势或客户选择理由 | 本人自述，并以已确认细节或动作支持 | 会员逐字评价、全体客户的动机或未经统计的优势排名 |

例如档案只说“如果会员一周只能来一次，我会调整训练”，正文也保持“如果”的条件；不能为增加故事感写成“有位会员原本每周来三次，后来改成一次”。发现句子把担忧、假设或推断升级成事实时，退回原语义；确需真实案例则向本人补问，不从 PDF 示例或其他教练档案借一个。

## 框架不等于文风

先看本人提供的原稿、语音原话和档案中的可观察特征：称呼方式、句子长短、爱用的细节、表达情绪强度、常见收尾和明确讨厌的词。只选择真正有证据的特征，不把“真诚、专业、有温度”当作可操作的文风描述。

写完后做三项对照：

- 这句话是否能在本人原话、实际行动或可公开经历里找到依据？
- 换成另一名教练还会完全成立吗？若会，补入本人的具体动作、现场或选择。
- 读给本人听是否像他会说的话？这一项只能由本人最终判断；没有反馈时标“语气待校准”。

不得把测试人物的口头禅设为所有教练的默认语气。新教练缺少表达样本时，先用平实口语写一稿，标记为试稿，再请本人指出最不像自己的 1～2 句进行修订。

## 从朋友圈框架到小红书

PDF 的“左侧框架”是表达顺序，“右侧例文”只演示一次填充。迁移时保留任务，不保留原句。一般组织为：

1. 标题：指出本地目标用户会在意的具体问题或人物选择，不夸大数字；
2. 开头：直接交代真实场景、客户顾虑或本人经历；
3. 正文：按选中子类的框架逐步给事实、行动和判断，段落短而可独立理解；
4. 收束：补一句本人立场、适用边界或真实问题。是否引导咨询取决于内容目的和实际服务，不默认“私信、加微信、限时抢”。

图文可建议真实场馆角落、教练本人、空白计划示意；口播可建议本人面对镜头讲一次真实咨询或服务动作。不得要求提供未授权会员照片、群聊截图、转账截图或含健康资料的训练手册。

## 四类内容的目的差异

- 人设型：让附近用户理解“这个教练是什么样的人、为什么这样做”。避免把价值观写成空口号。
- 营销型：解释“我担心的问题，你具体怎样交付”，用有来源的服务和授权案例建立信任。不能替换成硬广堆叠。
- 利他型：让读者当下看懂或尝试一项安全、有限的判断或沟通方法，承认个人差异。
- 流量互动型：提出真实而具体的问题以收集本地客群反馈，不假扮热点、制造对立或虚构自己没经历过的趣事。

若用户指定的题没有证据或不属于本地线下客群，先提示差异；不要靠四类标签强行把它写得像已验证的内容。
