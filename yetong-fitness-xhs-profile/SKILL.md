# 叶童健身教练人物底色访谈

把一名在具体城市、商圈或社区服务本地客群的健身教练，其真实人生经历、业务处境、本地客群、内容资产和表达习惯整理成唯一的人物 DNA 档案。默认先做能开始真实选题的短访谈；成长故事、会员案例和更细的文风在具体内容需要时补访。后续选题和文案 Skill 必须读取这份档案，不在各自目录中复制人物信息。

## 核心产出

交付一个 `person-dna.md` 文件。它既是本人可以检查的档案，也是下游 Skill 的人物信息真源。

档案必须区分：

- 已由本人确认的事实；
- 尚待确认的推断或缺口；
- 可以公开、仅可内部使用和禁止使用的信息；
- 真实经历、表达偏好与内容创作建议。
- 所在城市、实际服务半径、本地客群底色及经过事实支持的痛点地图。

档案结构见 [人物 DNA 结构](references/person-dna-schema.md)。

## 不变量

1. 不编造人生经历、会员案例、证书、成绩、数字、地点或人物关系。
2. 访谈以对话推进，每轮只问 1～3 个彼此相关、会改变档案的问题，不一次抛出长问卷。
2a. 限制每轮问题数量不等于限制总成本。默认先完成基础可用档案并尽早给确认摘要；不为了填满八个访谈模块追问一小时。用户主动想深谈人生时，再进入深访。
3. 用户说得口语化、跳跃或不完整时，先整理再复述确认，不要求用户重新组织。
4. 原话与 Agent 的归纳分开保存。没有获得本人确认的归纳不得写成确定事实。
5. 隐私权限与事实真实性同等重要。禁止公开的信息可以服务内部判断，但不能进入公开内容。
6. 只有状态为 `active` 的档案才算人物 DNA 已激活。`draft` 和 `pending_confirmation` 只能用于继续访谈或请求确认。
7. 更新档案时修改同一真源并提高版本号，不复制出互相冲突的人物档案。
8. 本 Skill 的对象是以本地线下客户为主要业务的普通健身教练。纯线上、全国招生或教同行获客不进入这套内容流程；教练若另有业务，可以作为背景记录，但下游目标始终是其本地潜在会员。
9. 不根据城市标签猜测客群。痛点必须来自教练的真实咨询、成交、会员案例、访谈或明确标注的待验证观察。
10. 不强迫真实经历出现戏剧性转折。长期重复的基础服务、稳定履约和普通训练日常也可以成为有辨识度的故事资产。
11. 追问服务、价格或售后承诺前，先核对用户此前给出的权益和书面规则；已经明确的内容不重复问。口述与既有规则不一致时，保留两种来源并标记待核实，不把临场措辞直接升级为公开承诺。

## 进入方式

### 首次建档

用户尚无人物档案，或下游 Skill 无法定位人物档案时：

1. 用 [访谈指南](references/interview-guide.md) 的「默认速启」先确认本地线下业务、实际服务区域、主要会员、一个有来源的客户问题及一个本人真实服务动作；优先从用户已有口述中提取，不重复问。
2. 从回答中保留一段自然原话作为初始表达样本；不足以判断文风时标明「语气待校准」，不因此强制索要旧稿。
3. 把当前身份、城市／场馆、服务动作的拟公开范围与其他材料的禁区合并成一次摘要，请本人核对；不要求先讲完整成长史或提供会员照片、效果数据。
4. 在本人确认前先保存 `draft` 或 `pending_confirmation`；满足基础条件且明确确认后即可激活。未访谈模块在同一档案标「尚未提供」，后续按需补足。

如果用户的业务主要面向全国线上客群，说明本 Skill 的本地业务假设不成立并停止，不把全国用户强行改写成本地客群。

### 继续访谈

已经存在 `draft` 时：

1. 读取已有内容；
2. 找出会阻碍后续内容工作的关键缺口；
3. 从上次停止位置继续，不重复已经确认的问题。

### 确认与激活

核心信息已经足够时：

1. 达到「基础可用」条件就输出一份便于本人检查的摘要，不等待八个模块全部填满；
2. 单列矛盾项、推断项、敏感项和拟公开边界；
3. 请求本人确认或更正；
4. 只有收到明确确认后，才把状态改为 `active` 并写入确认日期。`active` 表示已记录的信息获确认，不表示人生故事、会员案例和语气都已完整；下游只使用已知事实，缺什么就针对当篇内容补问什么。

### 更新档案

用户补充新经历、换城市、换场馆、调整业务或纠正旧信息时：

1. 保留新旧信息的时间范围；
2. 标明哪些旧事实已经失效；
3. 更新同一档案的 `profile_version` 和 `updated_at`；
4. 重大变化重新进入 `pending_confirmation`。

## 访谈顺序

默认速启只做下列第 1～3 项，加上一次公开边界与摘要确认。第 4～9 项是可选深访；若用户已自然提供，直接提取，不再提问。

优先完成会改变内容方向的字段：

1. 当前身份、所在城市、区县、场馆和业务；
2. 本地服务半径、客群构成和到店条件；
3. 本地客群的目标、显性痛点、隐性痛点、现实约束和成交障碍；
4. 产品、成交路径和与本地同行的差异点；
5. 入行、成长与关键转折；
6. 真实会员案例与可验证证据；
7. 价值观、立场和内容边界；
8. 说话习惯、常用词和讨厌的表达；
9. 人物关系、日常生活和可持续拍摄场景。

完整模块、追问方法和提前停止条件见 [访谈指南](references/interview-guide.md)。

## 最少提问原则

满足以下任一条件时才追问，且优先判断它是否阻碍**当前要做的选题或文案**；不影响当前产出的缺口留到以后：

- 答案会改变人物定位、目标客户或内容方向；
- 不清楚用户实际覆盖的城市区域、通勤范围或到店方式；
- 客群痛点只是行业常识，尚无本地咨询、案例或原话支持；
- 当前选题必须使用某段经历而档案缺少事实；否则先选有来源的服务场景，不为建档而强迫讲人生故事；
- 同一信息出现冲突，需要确定时间范围；
- 不清楚信息能否公开；
- 无法判断一句话是用户原话、他人评价还是 Agent 推断。

低风险的格式、标题和排序由 Agent 直接处理。

## 人物 DNA 就绪度

使用以下状态：

- `draft`：正在访谈，信息可以继续补充；
- `pending_confirmation`：核心档案已经形成，等待本人核对；
- `active`：本人明确确认基础档案，可以被下游 Skill 使用已知事实；缺少的故事、案例或文风仍不可推断；
- `needs_review`：业务、身份或公开边界发生重大变化，暂停个性化生成。

当下游请求发生在档案未激活时，原样使用下面的提示：

> 人物 DNA 尚未激活。当前只能调用通用方法，无法启用个性化选题、真实经历映射与个人表达校准。完成「人物底色访谈」并确认档案后，才能解锁完整的叶童内容方法引擎。

用户可以明确要求跳过访谈并获取通用结果，但下游输出必须标注“通用版本”，不得声称符合本人经历或个人表达。

## 保存规则

1. 优先使用用户明确指定的保存位置。
2. 未指定位置时，在第一次写入前只询问一次保存位置，不静默写入私人目录。
3. 文件名使用 `person-dna.md`；多人建档时，每人使用独立目录。
4. 不把人物档案、访谈原文或私密案例写入本 Skill 目录。
5. 写入后运行：

   ```bash
   python3 scripts/validate_profile.py /path/to/person-dna.md
   ```

6. 校验失败时保持原状态，修正结构后再请求本人确认。

## 下游交接

选题、文案和主入口 Skill 接入人物档案时，读取 [下游读取契约](references/downstream-contract.md)。

下游结果必须能指出：

- 使用了哪些已确认的人物信息；
- 哪些创作判断来自人物 DNA；
- 哪些事实仍然缺失；
- 是否触碰公开边界。

## 隐私与证据边界

- 会员案例默认去标识化；公开姓名、照片、聊天记录和健康信息前，要求用户确认已有授权。
- 小城市、固定场馆和窄客群容易被反向识别；即使隐去姓名，也要检查组合信息是否暴露具体会员。
- 医疗、康复和训练效果不得从单个故事上升为普遍保证。
- 他人对用户的评价要标明来源，不把自我评价伪装成第三方背书。
- 身份、证书、业绩和效果数字没有证据时标为待确认。
- 不读取用户没有主动提供或授权的私人文件、聊天记录和联系人信息。

## 完成条件

默认「基础可用」访谈在以下条件满足时完成：

- `person-dna.md` 符合结构要求；
- 本地线下业务、真实服务区域或到店情境、主要客群已明确；
- 至少一个有来源的真实客户问题和一个本人确实在做的服务动作已记录，可支撑首轮选题；
- 目前能观察到的本人原话已保存；样本太少时明确标「语气待校准」；
- 拟公开的当前事实、其余材料的未知权限、矛盾与缺口已单列；
- 本人已经明确确认档案；
- 状态为 `active`；
- 校验脚本返回成功。

没有成长故事、授权会员案例或完整生活资料，不阻止基础档案激活，但相应类型的个性化内容仍不得编造。若基础事实或公开边界尚未确认，保存为 `draft` 或 `pending_confirmation`，不能为缩短流程而擅自激活。用户愿意时可继续深访；不把深访作为获得第一个可用选题的前置收费时间。
