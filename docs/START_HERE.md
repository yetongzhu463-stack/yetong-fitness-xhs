# 第一次使用 YETONG

这份说明写给第一次接触 YETONG Skill、不会编程、也没有使用过命令行的健身教练。

## 它能帮你做什么

YETONG 是给**主要服务本地线下会员**的健身教练使用的一组 Agent 工作方法。目前已经能帮助你建立自己的人物 DNA，做小红书选题、文案、标题、体检和封面，也能为一门具体课程梳理目标会员、购买理由和每天的朋友圈推广文案。本次发布修订为 `0.9.1`，仍包含 10 个 Skill；每日热点每次固定给 3 题，归内容线。本修订加强更新与安装验收，GitHub 实际已发布版本以远端清单为准。它不是自动获客软件，也不保证播放量、咨询量或训练效果；内容会要求有本人依据，避免把别人的故事写成你的经历。

Skill 可以理解为交给 Agent 的一份“专门工作说明书”。普通聊天需要你一次次解释自己的业务和写作要求；安装并使用这组 Skill 后，Agent 会按相应流程判断该先了解你、找选题，还是处理已有稿件。你的私人档案应保存在你自己可访问的位置，不放进公开 Skill 包。

## 安装后，先说这一句话

**安装完成并不等于 Agent 会自动弹出欢迎消息。** 不同 Agent 的安装界面不同，Skill 本身不能在所有客户端监听“安装成功”事件。打开一个新对话，发送：

> 使用 `yetong`，展示当前实际已安装的 YETONG 全部技能，按“小红书内容创作、朋友圈营销、业绩管理”三类介绍每项能做什么、怎么触发；已开发但本机缺失的标“未安装”，尚未开发的标“规划中”。然后告诉我第一步该做什么。

如果 Agent 能读到 `yetong` 主入口及登记表列出的模块，它应按实际证据展示菜单：小红书内容与课程朋友圈营销已有模块，泛朋友圈场景尚未覆盖，业绩管理仍规划中。规划／未覆盖不是安装缺失，不需要补装，也不应出现杜撰的业绩技能调用名。目录数量随登记表变化，不靠介绍里的固定数量判断。文件与哈希校验通过、当前宿主已发现并调用、新任务仍可读，是三层不同验收；哪层没测就写未验证，不把一份菜单当作全部通过。

若所用 Agent 允许安装 GitHub Skill，也可以把安装和介绍合成一句话：

> 请全程用中文，从官方仓库 `yetongzhu463-stack/yetong-fitness-xhs` 实际安装全部 YETONG Skill 到当前环境支持的技能库；已有同名目录先核对归属并备份。返回真实执行结果、安装或注册位置，按远端清单核对版本与完整资源，并检查当前宿主是否能调用，再使用 `yetong` 展示三类菜单。没有工具或不能安装就说明具体缺口；未测跨任务保存就标未验证，不要只说准备执行或展示网页就结束。

这是一条给 Agent 的请求，不是所有平台都能执行的自动安装协议；若安装与调用分成两步，使用上面的“安装后”一句话即可。

底层命令仍是 `npx -y skills add yetongzhu463-stack/yetong-fitness-xhs -g --all`，不包含本包版本号；仓库地址不变时不必每次更新都换口令。保留短横线，不换成排版长横杠。Agent 应先检查安装器当前的 Node／Git、联网和权限要求，运行本包另需 Python 3.9 以上。原安装器可能重建同名目录，因此已有更新模块时优先说“更新叶童技能”；重装前确认档案放在包外并备份已安装的同名目录。

WorkBuddy 手机端可在官方“添加技能”入口选择已装技能；云端与连接电脑是不同模式，需分别检查，不能把 CodeBuddy 适配项当作 WorkBuddy。豆包也须在支持工作任务与技能的环境核对；文件下载成功不自动证明补装已注册或永久保存。请按照当前宿主实际界面启用／导入，不让 Agent 编造加载命令。看到 `vercel-labs/skills` 页面只是安装工具介绍，本包仓库是 `yetongzhu463-stack/yetong-fitness-xhs`。

## 第一次真正开始

先告诉 Agent：“请用 `yetong-dna` 帮我建立人物档案。”它应先说：

> 请回答下面几组问题，可以一起答，口语就行，但一定要越详细越好，我来整理。稍微要有点耐心，这会决定以后你的文案质量。

然后一次展示六组问题，你可以用一段语音或文字一起回答：

1. **业务定位**：在哪个城市、区域、场馆带课，核心业务是什么；用一句话说明场馆优势。
2. **到店会员**：主要来自哪里、通勤多久、服务最多的是哪类人；他们想解决什么，又被哪些实际顾虑或困难卡住。
3. **客户问题**：最近常听到的一个顾虑或咨询，尽量保留原话；你实际怎么处理。
4. **你是谁**：称呼、角色、从业时间、真实资质与擅长项目、课程标准、课外服务及实际做法。
5. **高光经历**：最骄傲的三件事，以及一个匿名会员的真实变化；暂时没有的可以直接说没有。
6. **为什么选择你**：用一句话说清个人核心优势；如果有会员的实际评价，也可以提供原话并区分来源。

第一组先问真实服务城市，不预设任何地点；你已经明确提供的信息会直接沿用。例子不是标准答案，不用为了凑满三件高光、证书或成功案例编造。默认这六组就是建档全部范围，回答后由 Agent 整理，只对影响事实或激活的关键缺口集中补问；你想分组回答也可以。若当前 Agent 不能读取音频，请用手机语音输入转成文字，不会假装已经听过录音。

请亲自核对整理后的事实、公开范围和表达习惯，并在确认后激活自己的 `person-dna.md`，保存在 Skill 安装目录之外。新资料会按当前任务需要供选题、每日热点、文案、标题、体检、封面和课程朋友圈营销共同取用，不会每篇堆满所有资料。旧版已激活档案仍可继续用，不要求重新回答整套问题；语音整理尚未确认时也不会自动激活。

要做个性化选题或文案时，把**自己**的已激活档案路径交给 Agent。没有激活档案，或档案属于另一位教练时，不应生成声称“像你本人”的内容。你也可以先看[完整技能目录](SKILL_CATALOG.md)，直接说出自己现在的需求，由 `yetong` 匹配已可用的技能。

做封面时，先交给 `yetong-cover` 一个已定选题或草稿，再按叶童原版流程一次回答一个选择题：选构图、上传图1人物参考、补充素材、选动作、选背景、确定封面文字。已有信息会直接沿用，不重复问；回复编号后会继续当前封面流程，不重新出选题。图1缺失时等你上传，不会改做无人物海报，也不会凭文字虚构你的脸或门店。不露脸可以用手部、背影或局部参考图。

原版使用 3:4 真人实拍构图、顶部与底部巨字、白色与暖橙黄（`#F5A623`）的固定视觉语言，不使用漫画式粗描边。明确给出的封面文字原样保留；没给文字时提供三个候选供你选编号，不自动改笔记发布标题。收集完成后给方案摘要、完整生图提示词、文字排版清单与生成约束；默认提示词包含文字，只有你明确要无字底图才留出叠字区。

完成可执行提示词后会问：“需要根据这份提示词完成封面吗？回复‘直接生成’或‘继续优化提示词’。”你只想拿提示词也可以，不会被催着生成。当前 Agent 没有生图工具、缺素材或缺授权时，会说明真实缺口；选择直接生成仍须核对这些条件，不能把提示词交付说成图片已经生成。

## 推广一门新课

建档后，把这门课的资料交给 Agent，例如课程内容、适合人群、实际标准、价格与权益、你已有的素材，以及目前是草案还是已确认可以交付。可以直接说：

> 这是我的已激活档案路径和课程介绍。使用 `yetong-promo`，帮我梳理这门课卖给谁、优势与顾虑，再安排每天发什么朋友圈。

它会结合你的本地客群与真实服务，整理产品说明、客户选择理由、真实反馈／结果、成交／复购等内容，并对应到现有营销型的客户咨询、客户反馈、转账截图、会员蜕变结构。没有某类证据，就安排收集动作或换成真实的课程说明，不伪造收款、会员评价、排队或效果图。推广频率按你的素材和执行能力安排，不承诺每天固定发几条就会成交。

新课程用独立产品资料卡，不用每次重做整份人物 DNA。草案可以先做内部策划，但提纲会明确不可直接发布；写对外文案前要核实课程真实可交付，不能把草案写成已开课。已有计划时，直接说“按这个计划写今天的朋友圈”或“改成三天推广”，它会保留同一产品卡继续处理。价格、名额、优惠、服务权益和会员证据由你提供、确认，不由系统编造；与本人身份、业务能力或公开承诺冲突的才回人物档案核对。

当前朋友圈只上线具体课程产品营销，不等于泛朋友圈人设或日常运营已上线；业绩管理仍未交付专项 Skill。看到一类介绍，也不代表相关模块已在本机安装；以菜单核验为准。

## 每天给我 3 个热点选题

确认本机已安装 `yetong-timer` 后，可以说：

> 根据我的DNA帮我进行定时任务选题，每天定时给我3个热点选题。这是我的已激活档案路径：〔实际路径〕；每天〔时间〕执行，时区为〔时区〕。

它会结合你本人 DNA 和可核实热点，每次给 3 个面向你所在区域潜在会员的选题。抖音可以作为热点来源，受众不会因此改成教练同行；可以用泛曝光建立专业信任，不要求每题强卖课。想先看效果时，说“根据我的 DNA 试跑一次热点选题”，只执行这次选题，不自动创建任务。不会顺便扩写脚本、发布标题、封面或发布。

没有已激活的本人 DNA 时，先完成建档；只缺档案路径、时间或时区时，只补问缺项，不会替你定为 9 点或一律中国时区。创建前先核对已有同类任务，并确认当前 Agent 的原生调度能读取这份 DNA 和热点方法。任务创建以宿主返回的可核对任务标识、启用状态、时间与时区为依据；安装了 Skill、看到选题示例或一次试跑成功，都不等于后台已经安排好。豆包和 WorkBuddy 是否具备可用的原生定时能力，要在你当前环境核实；本包没有声称手机云端已实测，也不能编造创建接口。

普通“给我5个选题”仍由 `yetong-topic` 处理；“朋友圈每天4条计划”仍由 `yetong-promo` 做课程计划，不自动注册调度。取消或其他调度管理请使用当前 Agent 的原生任务列表；每日热点模块不是通用任意任务服务。

## 以后更新，只说一句话

当前安装里有 `yetong-update` 后，说“更新叶童技能”即可；在 YETONG 主入口任务中只说“更新”也会进入包更新。想先了解版本，说“检查叶童技能更新”。更新不要求先完成人物 DNA；“更新我的城市／档案”仍是修改人物资料。

它会从官方 GitHub 仓库核对发布版本和运行文件，更新当前这套安装，并加入新发布、已登记的技能。API 受限时通过官方归档元数据回退，重新获取固定提交，不需要你提供账号密钥。人物档案、其他技能和未受管文件保留；失败会恢复本次修改。成功后按宿主真实支持的方式启用／刷新，再检查菜单与调用，不宣称重开一定成功。旧版缺更新模块或老更新器无法取新版时，先核对归属、备份同名目录、确认私人档案在包外，再用原安装方式导入，不能假设重装保留目录内未知文件。

需要当前 Agent 可以联网、执行 Python，并有持久可写的 Skill 目录。平台托管的技能库或手机独立云端若不允许直接更新文件，应通过它自己的导入／更新入口操作；模块会说明限制，不能只因一句“更新成功”就认为下一次云端任务也保留了新版本。
