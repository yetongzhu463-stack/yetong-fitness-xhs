# 叶童写作感 0.1.0

把用户手里的材料写成适合眼前读者的中文作品。先完成本轮任务，让材料、说话位置和表达彼此接得上。作者可以直接、有情绪、有判断，不必变成面面俱到的机构口吻。

## 不变量

1. 现实稿不新增用户没给的经历、动作、症状、诊断、数字、原话、心理和动机。看见不能改成做过，自述不能升级成核实结论。
2. 原材料的判断可以保留锋芒；区分观察、个人观点与因果证据，不把个例扩成全体，也不偷偷换掉作者的立场。
3. 虚构可以创造人物、经历、对白和心理，检查人物所知、时间、因果与世界规则。混合任务分开现实承诺与虚构部分。
4. 每段增加一件事情或承担一种必要作用。重复讲同一建议的意义、好处和后果，仍算重复。
5. 文体、语气、篇幅和改写幅度服从本轮请求。保留有用的原句，不把轻改变成重写，不固定套入教练身份、推广、编号清单或互动号召。
6. 事实与任务错误必须修复。正常纠正、自然递进、冒号、破折号和文学表达可以使用；词法提示不能代替语境判断。
7. 只交本轮需要的作品。必要的关键提问、材料或篇幅冲突简短说明；不展示内部推理、事实清单、审稿过程或检测报告。

## 第一步：确定本轮要交什么

从请求和上下文确定作者、读者、文体、现实性质、篇幅、改写幅度。已经知道的不要再问。轻改优先保留句子与结构；重写可以重排，但保留事实、核心意图和已经成立的声音。

明确要求代码、翻译、公文或技术文档时，尊重原任务，不强套本 Skill 的散文风格。

只在缺口会改变作品、事实归属或能否交付时追问。一次优先问一个能带来新内容的问题，多个依赖缺口最多三个。不要为一次短文请求做作者访谈。

依据：修辞情境，用当前目的、读者和限制决定表达。

## 第二步：判断材料能写到哪里

先按 [任务与材料](references/task-and-material.md) 判断可写事实、作者判断、未知以及允许的创造。

- 短文材料够用就写，不套长文素材数量门槛；没有明确长文需求，不自动拉成长文。
- 长文检查关键主张、过程与细节是否各有支撑。固定数量不是内容充分的证明，抽象观点的换说法不增加材料。
- 公开事实有必要补证时研究；用户禁止联网则遵守。不能拿没有发生的检索或亲测作开头。
- 依赖私人经历的关键缺口，先问；不索要与当前任务无关的额外症状、隐私或人生背景。
- 扩写会引入事实、反复说同一件事时停止。能通过必要解释或明确的作者判断自然补足就交稿；做不到就补料。
- 用户明确不许追问时交材料能支撑的短稿，必要时一句话说明未达到所要求的篇幅，不能假称达标。

材料预算是经验判断，不是普遍字数公式。

## 第三步：只读本轮需要的细则

| 任务 | 读取资源 |
|---|---|
| 通用散文、知乎、公众号、评论、长帖或大幅重写 | [中文组织与作者声音](references/forum-prose.md) |
| 真人、现实事件、产品、数据、商业判断、个人经历 | 另读 [现实边界](references/reality.md) |
| 小说、故事、对白、虚构散文 | [虚构叙事](references/fiction.md)；帖子体故事再加通用散文 |
| 朋友圈、短文、口播、教程、评测、剧本或诗歌 | [形式适配](references/formats.md) 的相关部分 |
| 初稿完成后 | [分级审稿](references/revision.md) |

不预先加载所有文件。短文无需为通用长帖示范付出完整阅读成本。现实与虚构边界贯穿全程，诗歌和实验写作不强行套散文问答链。

## 第四步：从说话位置写初稿

明确谁在说、凭什么知道、为何现在想说、眼下最在意什么，以及读者接下来会问什么。缺少事实不能靠补口头禅、场景道具或空泛情绪制造真实感。

现实稿顺着材料和局部问题推进；虚构稿顺着人物的目标、行动与变化推进。背景在解释眼前事情时出现，不一次倒完。

优先交代谁做了什么，再补时间、原因、条件。保留指向清楚的重复词，让长短句跟着内容走，不为句长数字添句或拆句。

情绪已经通过动作表达，就少解释一句；动作传不出的心理、神态和权衡应保留，尤其是第一人称与近距离虚构。

短篇可以只讲一次感受或一个判断，不必同时给方法、行业解释和人生提醒。写到事情结束就停。

依据：QUD 帮助组织问题推进；读者预期帮助排列信息。它们不覆盖所有文学形式。

## 第五步：先核内容，再修语气

初稿后读取分级审稿，至少完成：

1. 对照输入：是否新增现实动作、数字、引语、症状、动机、心理或因果强度；所有重要新增公开事实有无真实依据。
2. 检查任务：文体、读者、作者意图和改写幅度是否改变，是否擅加推广或结尾号召。
3. 检查推进：每段新增什么；删一段是否只少了一次相同提醒；能删且意思没损失就删。
4. 检查语言：先处理指向和词序，再处理重复、黑话和姿态。正常纠正、原有具体判断不因形式相似而自动删除。
5. 虚构复核人物所知、场景变化、时间与设定，保留必要心理。

事实核对与输入对照由模型判断，下面的工具不能证明事实正确。

## 第六步：核对篇幅，按需运行工具

用户指定篇幅或稿件较长时运行 [检查脚本](scripts/check_writing.py)。词表与启用条件统一见 [规则数据](references/style-rules.json)，审稿正文不另建重复词表。

```bash
python3 scripts/check_writing.py draft.txt --genre social --target 300 --format json
python3 scripts/check_writing.py draft.txt --genre spoken --target 200
python3 scripts/check_writing.py draft.txt --count-mode han --target 300 --tolerance 0
```

约 N 字默认按传入正文的非空白字符数计，含标点，容差 ±10%；同时记录汉字数。用户另有口径时使用其口径。传给工具的文件只放要计数的作品，不混入说明和审稿报告。

工具报告规则编号、位置和复核线索。退出 0 仅表示没有机器可确定的硬失败；有 review 时仍需判断。退出 1 是配置的篇幅或显式禁项未满足；退出 2 是输入错误。不能为让工具返回 0 而改变事实或重复凑字。

有朗读能力时朗读口播并计时；仅有文字工具时检查停顿与顺口程度，不宣称实际朗读或实测时长。

## 交付与停止

- 用户只要成稿时只交作品，保留必要引语、标题或来源，不附检查记录。
- 全靠公开材料形成的现实事实稿，按需要列少数关键来源；个人感受和观点稿不自动附研究笔记。
- 无法同时满足事实、非重复和篇幅时，用最少问题取得关键材料，或按“不许追问”的要求交短稿并说明冲突。
- 不建立长期作者画像，不自动发布，不把单条任务写入其他项目或个人规则库。

来源与改编说明见 [provenance](references/provenance.md)。本地测试输入和评分记录位于 evals，不参与日常写作加载。
