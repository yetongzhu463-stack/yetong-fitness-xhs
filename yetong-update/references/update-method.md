# 更新方法与验收

## 发布契约

官方仓库为 `yetongzhu463-stack/yetong-fitness-xhs`，分支为 `main`。脚本先通过 GitHub API 获取分支提交号；API 限流、网络失败或未返回有效提交时，回退到 `codeload.github.com` 的官方分支归档，在有界 PAX 元数据中读取严格的提交号，然后**重新下载该不可变提交**的源码快照。浮动分支归档只提供提交号，其内容不直接安装。读取 `yetong/references/release-manifest.json`，列出本次版本、运行 Skill 名称和逐文件 SHA-256；清单自身不加入哈希列表，避免循环。技能成员由能力登记表生成，未来新增并启用的模块会一起更新。不需要 Git、账号凭据或第三方镜像。

快照须同时满足：仓库与分支固定、路径在声明的 Skill 目录内、无路径穿越或文件链接、所有声明文件哈希正确、目录名与 `SKILL.md` 名称一致、登记表成员与清单一致、引用文件齐全。下载与解压限制大小和耗时。完成校验后才写入安装目录。

HTTPS 始终核验证书和主机名；若 Python 默认根证书为空且没有用户指定的证书配置，更新器会尝试平台现有的系统证书包，仍不可用时提示修复证书环境。

HTTP 403 也可能与权限或其他策略有关，只有实际错误、响应头等证据明确时才判断限流。没有取得重试时间就不估计恢复时间；官方通道全部失败或提交元数据不可靠时安全停止，获取阶段不改安装文件。宿主受限时明确报告相应渠道原因，不以反复请求、关闭证书校验、上传密钥或自动创建重试任务作为替代。

## 安装范围与保护

默认目标是更新脚本真实路径所在的 Skills 根目录。标准安装中，Agent 的 Skill 入口可能链接到共同目录；解析当前脚本可定位该共同安装实例。目标目录中的模块链接若指向其他安装根、目标带源码仓库标记、或存在同名未知技能，脚本停止并说明原因。它不搜索其他 Agent，不修改版本管理设置，也不改变其他 Skill。

已有发布清单用于证明旧文件归属。没有清单的早期安装，仅将其有效 YETONG 登记表列出的模块文件和已知主入口运行文件视为旧文件；其他内容保留。新增托管文件撞到未知文件时停止。更新不删除旧版移除的模块目录，报告它们已不在当前登记表中；用户可另行处理。

## 文件事务

缺更新模块或旧更新器无法获取新版时，重新安装／导入是另一个工作流，并不继承上述事务保护。安装器可能清空同名目录：先核对目录归属，备份目录中原有文件，确认人物档案存放在包外及目标实例相同，才能接入新版；不得把未知同名技能直接覆盖。旧更新器不会自行获得本地尚未发布的补丁，新版首次接入后才具备新的备用获取通道。

脚本加锁后重新检查目标状态，在目标目录的同级专用备份位置保存将被覆盖的旧文件和操作记录。每个文件以临时文件替换。全部写入后核对哈希、登记关系和菜单；任一写入或验收失败时，恢复旧文件，并移除本次新建的受管文件。未知文件始终保留。备份包含本次触碰的运行文件，不收集人物档案。

`check` 只读检查，不下载到安装目录。`apply` 可修复同版本缺失或损坏的文件。输出 `updated` 或 `up_to_date` 才表示当前实例运行文件验收通过；输出备份路径便于必要时检查旧文件。版本号相同但文件哈希不一致时，不得误判“已经是最新”。

## 宿主边界

更新依赖宿主真实提供的执行、网络和写入能力。只允许上传技能的服务需重新导入；不可写的插件缓存需通过宿主插件更新入口处理。云端任务中是否持久保留文件由宿主决定，应在重开任务后核对版本和技能菜单，不能以本次脚本成功代替持久化验收。
